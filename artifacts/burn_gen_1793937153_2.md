# FOC Motor Control and Dual-IMU Sensor Fusion for a 3-Axis Gimbal

I don't have the Job #47 hardware specification, so this design is built on explicit assumptions (Section 0). Every gain is derived from motor or plant parameters rather than hard-coded. If your motor, encoder or MCU differ, change the constants in `GimbalConfig` and the gains recompute automatically.

## 0. Baseline Assumptions

| Item | Assumed value |
|---|---|
| Motor | Gimbal BLDC, 12N14P (pole pairs p = 7), R_s ≈ 5–15 Ω, L_s ≈ 1–4 mH |
| Rotor encoder | 14-bit absolute magnetic encoder (AS5048A or MA730 class), SPI |
| MCU | Cortex-M4F/M7 with single-precision FPU (STM32G4/H7 class) |
| PWM | 20 kHz center-aligned, 3 half-bridges, in-phase low-side shunts |
| Current loop | 20 kHz (runs in the ADC ISR) |
| Velocity loop | 4 kHz |
| Angle/attitude loop | 1 kHz |
| IMUs | 2 × ICM-42688-P on the camera plate, 8 kHz ODR, ±2000 dps, ±16 g |
| Axis order | Yaw (outer) → Roll → Pitch (inner, camera) |

## 1. Field-Oriented Control (innermost loop)

### 1.1 Transforms

**Clarke transform** (amplitude-invariant, assuming i_a + i_b + i_c = 0):

$$
i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}(i_a + 2i_b)
$$

**Park transform**, with electrical angle θ_e = p·θ_m − θ_offset:

$$
\begin{bmatrix}i_d\\ i_q\end{bmatrix}=
\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}
\begin{bmatrix}i_\alpha\\ i_\beta\end{bmatrix}
$$

**Inverse Park transform:**

$$
v_\alpha = v_d\cos\theta_e - v_q\sin\theta_e,\qquad v_\beta = v_d\sin\theta_e + v_q\cos\theta_e
$$

### 1.2 Plant and Current-PI Design

The d–q machine model (SPMSM, L_d ≈ L_q = L) is:

$$
v_d = R i_d + L\dot i_d - \omega_e L i_q,\qquad
v_q = R i_q + L\dot i_q + \omega_e L i_d + \omega_e\lambda_m
$$

**Decoupling feedforward.** Adding the following terms leaves each axis as the first-order plant 1/(Ls + R):

$$
v_d^{ff} = -\omega_e L i_q,\qquad v_q^{ff} = \omega_e (L i_d + \lambda_m)
$$

**Pole-zero cancellation.** For a PI controller C(s) = K_p + K_i/s, choose K_i/K_p = R/L. The closed loop then becomes the first-order system ω_c/(s + ω_c), with:

$$
\boxed{K_p^{i} = L\,\omega_c,\qquad K_i^{i} = R\,\omega_c}
$$

Choose ω_c ≈ 2π·1.5 kHz, which is at most f_PWM/10 after accounting for the 1.5·T_s computation-plus-PWM delay.

**Voltage limit.** Clamp the voltage vector circularly so that |v_dq| ≤ V_bus/√3, the linear SVPWM region.

### 1.3 SVPWM via Min/Max Zero-Sequence Injection

This is mathematically equivalent to sector-based SVPWM:

$$
v_{off} = -\tfrac12\big(\max(v_a,v_b,v_c)+\min(v_a,v_b,v_c)\big),\qquad
D_x = \tfrac12 + \frac{v_x + v_{off}}{V_{bus}}
$$

The phase voltages come from the inverse Clarke transform:

- v_a = v_α
- v_b = −½v_α + (√3/2)v_β
- v_c = −½v_α − (√3/2)v_β

### 1.4 Discretization

Each PI is implemented with a backward-Euler integrator and back-calculation anti-windup, where u_sat is the clamped output and K_aw ≈ 1/T_s · (K_i/K_p)-normalized:

$$
\begin{aligned}
u_k &= K_p e_k + I_k\\
I_{k+1} &= I_k + T_s\big[K_i e_k + K_{aw}(u^{sat}_k - u_k)\big]
\end{aligned}
$$
