# Gimbal FOC Control and Dual-IMU Fusion Design (Job #47)

I don't have the Job #47 spec sheet, so this design uses the assumptions below. Every assumption is a single constant in the code, so you can swap in your real values.

| Parameter | Assumed value |
|---|---|
| Motor | Gimbal BLDC, 12N14P (7 pole pairs), R ≈ 5 Ω, L ≈ 2 mH, Kt ≈ 0.08 N·m/A |
| Position sensor | 14-bit magnetic encoder (MT6701/AS5048), used for commutation |
| Current sensing | 2-shunt or inline, center-aligned PWM sampling |
| IMUs | 2 × ICM-42688-P on the camera plate, SPI, FSYNC/CLKIN-synchronized |
| MCU | Cortex-M4F/M7 with single-precision FPU (STM32G4/H7 class) |
| Loop rates | Current 24 kHz · IMU 8 kHz ODR → 4 kHz · Velocity 4 kHz · Attitude 1 kHz |

## 1. System Architecture

```
            ┌────────── 1 kHz ──────────┐ ┌──── 4 kHz ────┐ ┌───── 24 kHz ─────┐
 q_ref ──►(Attitude P)──ω_ref──►(+)──►(Velocity PI)──iq*─(+)─►(Current PI dq)─►SVPWM─►Motor
             ▲                    ▲  -        ▲            ▲       ▲
             │                    │           │     iq_cog(θm)     │ id,iq (Park)
       q̂ (Mahony)        ω_joint = J⁻¹ω_cam  ω_ff          │       │
             ▲                    ▲                  Cogging FF   θe = p·θm (encoder)
             └─── Dual ICM-42688-P → AAF → LPF → Notches → Fusion
```

Design principles:

- **Commutation uses the encoder.** The current loop and the cogging table run from the motor's encoder angle.
- **Stabilization uses the camera IMU.** The velocity and attitude loops are closed on the camera-plate IMU, because the camera is the object we want to stabilize.
- **Joint mapping.** Joint rates come from the camera body rate through the gimbal inverse Jacobian, ω_joint = J⁻¹(θ)·ω_cam.
