# FOC Control Loop and Dual-IMU Sensor Fusion for a 3-Axis Gimbal

I don't have the Job #28 specification, so this design uses common gimbal hardware assumptions. These are listed in §0. Change the constants in `config.hpp` to match your hardware. The equations and structure do not depend on those values.

---

## 0. Assumptions and Timing Architecture

| Item | Assumed value |
|---|---|
| Motors | Gimbal BLDC, 12N14P (pole pairs p = 7), R ≈ 5–15 Ω, low Kv |
| Rotor sensor | 14-bit magnetic encoder (AS5048A/MT6701) on each axis |
| IMUs | 2× ICM-42688-P on the camera plate, SPI, ODR = 8 kHz |
| MCU | STM32G4/H7 class with FPU, center-aligned PWM, synchronous ADC |
| Current sensing | 2-phase low-side or inline shunts |

| Loop | Rate | Ts | Target bandwidth |
|---|---|---|---|
| Current (d/q PI) + SVPWM | 20 kHz | 50 µs | ~1.5–2 kHz |
| Velocity PI (gyro feedback) | 4 kHz | 250 µs | ~150–250 Hz |
| Angle PI (attitude feedback) | 1 kHz | 1 ms | ~15–30 Hz |
| IMU filter chain + fusion | 4 kHz (8 kHz ODR, decimated ×2) | | |

**Bandwidth separation rule:** each outer loop should have at most 1/5 to 1/10 of the bandwidth of the loop inside it. Then the inner loop can be treated as unity gain when tuning the outer loop.

## 1. FOC Inner Loop Equations

### 1.1 Electrical angle

$$\theta_e = p\,(\theta_m - \theta_{off}) \bmod 2\pi$$

θ_off is found at startup by applying V_d along the α-axis and reading the encoder.

### 1.2 Clarke transform (amplitude-invariant, balanced currents i_a + i_b + i_c = 0)

$$i_\alpha = i_a,\qquad i_\beta = \frac{1}{\sqrt3}(i_a + 2 i_b)$$

### 1.3 Park transform and its inverse

$$\begin{bmatrix} i_d \\ i_q\end{bmatrix} = \begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix} i_\alpha \\ i_\beta\end{bmatrix},\qquad \begin{bmatrix} v_\alpha \\ v_\beta\end{bmatrix} = \begin{bmatrix}\cos\theta_e & -\sin\theta_e\\ \sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix} v_d \\ v_q\end{bmatrix}$$

### 1.4 PMSM dq model (surface-mount, L_d = L_q = L)

$$v_d = R i_d + L\dot i_d - \omega_e L i_q,\qquad v_q = R i_q + L\dot i_q + \omega_e L i_d + \omega_e \lambda_m$$

$$\tau_m = \tfrac32 p \lambda_m i_q = K_t i_q$$

### 1.5 Current PI by pole-zero cancellation

Choose the PI zero to cancel the electrical pole R/L:

$$K_{p,i} = \omega_{bw} L,\qquad K_{i,i} = \omega_{bw} R \quad\Rightarrow\quad \frac{i_q}{i_q^*} = \frac{\omega_{bw}}{s+\omega_{bw}}$$

Decoupling and back-EMF feedforward:

$$v_d^* = PI_d(e_d) - \omega_e L i_q,\qquad v_q^* = PI_q(e_q) + \omega_e L i_d + \omega_e\lambda_m$$

**Voltage limiting:** apply circular limiting $\sqrt{v_d^2+v_q^2} \le V_{dc}/\sqrt3$. Give d-axis priority.

> **Note on high-R gimbal motors (R > 10 Ω):** if current sensing is unavailable, use voltage-mode. Set $v_q^* = R\,i_q^* + \omega_e\lambda_m$ and $v_d^* = -\omega_e L i_q^*$. Everything above this loop stays the same.

### 1.6 SVPWM by min/max zero-sequence injection

This is equivalent to sector-based SVPWM.

$$v_{a,b,c} = \text{invClarke}(v_\alpha,v_\beta),\qquad v_0 = -\tfrac12(\max + \min)$$

$$d_x = \tfrac12 + \frac{v_x + v_0}{V_{dc}}$$

## 2. Discrete PI/PID with Anti-Windup

Use Tustin/backward-Euler discretization with back-calculation anti-windup.

**PI law:**

$$u_k = K_p e_k + I_k,\qquad u_k^{sat} = \text{sat}(u_k)$$

**Integrator update with back-calculation** (K_aw ≈ K_i/K_p, i.e. 1/T_i):

$$I_{k+1} = I_k + T_s\big[K_i e_k + K_{aw}(u_k^{sat} - u_k)\big]$$

**Derivative on measurement** (only where no gyro rate is available), with first-order filter bandwidth N:

$$D_k = \frac{\tau}{\tau + T_s}D_{k-1} - \frac{K_d}{\tau + T_s}(y_k - y_{k-1}),\qquad \tau = 1/N$$

**Setpoint weighting** (b ∈ [0, 1]) reduces overshoot on step commands:

$$e_{p,k} = b\,r_k - y_k$$

## 3. Cascaded Angle and Velocity Control

### 3.1 Feedback signals

In a gimbal the *stabilized quantity is camera attitude*, not motor angle.

**Angle loop:** the attitude error is mapped to each joint.

$$e_{\theta,j} = J^{-1}(\mathbf q)\,\boldsymbol\phi_{err},\qquad \boldsymbol\phi_{err} = 2\,\text{vec}(q_{ref}^{*}\otimes q_{est})\cdot\text{sign}(\text{scalar part})$$

**Velocity loop:** uses the filtered gyro rate projected onto each joint axis. This feedback has far less latency than differentiating the encoder signal.

$$\omega_j = \mathbf{a}_j^{T}\,\boldsymbol\omega_{cam}$$

where a_j is joint axis j expressed in the camera frame. For the roll/pitch/yaw ordering, J⁻¹ comes from the gimbal kinematics. Near the nominal pose, J ≈ I.

### 3.2 Control laws

**Angle loop:**

$$\omega_j^* = K_{p,\theta}\,e_{\theta,j} + K_{i,\theta}\!\int e_{\theta,j}\,dt + \omega_{ff,j}$$

**Velocity loop**, with acceleration and anti-cogging feedforward added to the current command:

$$i_{q,j}^* = PI_\omega(\omega_j^* - \omega_j) + \underbrace{\frac{\hat J_j}{K_t}\dot\omega_j^*}_{\text{inertia FF}} + \underbrace{i_{cog}(\theta_m)}_{\text{§4}}$$
