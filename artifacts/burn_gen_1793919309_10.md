## 0. Scope, Architecture Decision, and Findings

### 0.1 Architecture

The STM32H743 does not commutate the motors. ArduPilot has no native BLDC commutation layer. The H743 also has neither the advanced-timer count nor the comparator/ADC topology to run 4 sensorless motors alongside a 1–2 kHz flight loop.

The standard partitioning is:

```
                 ┌──────────────────────────────┐
  6S LiPo ──────►│ Power stage (24 MOSFETs)     │──► M1..M4 (3φ each)
                 │ 4× 3φ gate driver            │
                 │ 4× ESC MCU (AT32F421 / AM32) │◄── DShot600 bidir (1-wire ×4)
                 └──────────────▲───────────────┘
                                │ VBAT, CURR, (ESC telem UART optional)
                 ┌──────────────┴───────────────┐
                 │ STM32H743 – ArduPilot         │
                 │ IMU(SPI), Baro(I2C), OSD, Rx  │
                 └──────────────────────────────┘
```

### 0.2 Findings that drive the design

1. **The burst current is thermally limited, not silicon-limited.** On a true 20×20 mm "nano" board, 4×80 A burst is sustainable for about 1 s from a warm start. That makes it a peak rating only (derived in §3). A 30.5×30.5 mm board roughly doubles that. Neither supports 80 A continuous.
2. **Conduction loss dominates.** At 80 A it is about 85% of power-stage loss, so R<sub>DS(on)</sub> and copper resistance matter more than switching speed.
3. **Input-capacitor ripple current is the hidden killer.** It is about 40 A RMS per ESC at D = 0.5. The external low-ESR bulk capacitor is mandatory, not optional.
4. **DMA allocation on the H743 is easy.** Because of DMAMUX1, the constraint is DMA stream count and ArduPilot hwdef rules, not fix
