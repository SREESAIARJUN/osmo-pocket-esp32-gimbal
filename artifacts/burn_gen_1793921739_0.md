# 3-Axis Gimbal: FOC Control Loop and Dual-IMU Sensor Fusion (Job #49)

## 0. Design Assumptions

I don't have the Job #49 spec sheet, so the design rests on the assumptions below. Every value is a `constexpr` or config field in the code, so you can substitute your real numbers.

| Item | Assumed value |
|---|---|
| MCU | STM32G474 / H7 class with single-precision FPU, about 170 MHz or more |
| Motors | Gimbal BLDC, 12N14P (pole pairs p = 7), R ≈ 10 Ω, L ≈ 3 mH (phase-equivalent) |
| Rotor sensor | 14-bit absolute magnetic encoder (AS5048A / MT6701) on each joint |
| Current sensing | Low-side shunts with ADC sampling synchronized to the PWM center |
| PWM | 25 kHz center-aligned. Current loop runs at 25 kHz. |
| Velocity loop | 5 kHz (every 5 PWM periods) |
| Angle (attitude) loop | 1 kHz |
| IMUs | 2× ICM-42688-P on the camera platform, on separate SPI buses, gyro ODR 8 kHz (decimated to 1 kHz after filtering), ±2000 dps, ±16 g |

Loop bandwidth separation is roughly 10× per stage: current about 1.5 kHz, velocity about 150 Hz, angle about 15–25 Hz.

## 1. FOC Inner Current Loop

### 1.1 Transforms

Electrical angle: θₑ = p·(θₘ − θ_offset), wrapped to [0, 2π).

**Clarke** (amplitude-invariant, i_a + i_b + i_c = 0):

$$i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}(i_a + 2 i_b)$$

**Park:**

$$i_d = i_\alpha\cos\theta_e + i_\beta\sin\theta_e,\qquad i_q = -i_\alpha\sin\theta_e + i_\beta\cos\theta_e$$

**Inverse Park:**

$$v_\alpha = v_d\cos\theta_e - v_q\sin\theta_e,\qquad v_\beta = v_d\sin\theta_e + v_q\cos\theta_e$$

### 1.2 Plant and PI Tuning by Pole-Zero Cancellation

The dq plant is:

$$L\frac{di_d}{dt} = v_d - R i_d + \omega_e L i_q,\qquad L\frac{di_q}{dt} = v_q - R i_q - \omega_e L i_d - \omega_e \lambda_m$$

Using a PI controller C(s) = K_p + K_i/s with K_p = L·ω_c and K_i = R·ω_c gives the closed loop i/i* = ω_c/(s + ω_c).

- Choose ω_c ≤ 2π·f_pwm/15. At 25 kHz, ω_c = 2π·1500 rad/s.
- With L = 3 mH and R = 10 Ω: K_p ≈ 28.3 V/A and K_i ≈ 94 250 V/(A·s).

Decoupling and back-EMF feedforward, using estimated parameters:

$$v_d^{ff} = -\hat\omega_e \hat L i_q,\qquad v_q^{ff} = \hat\omega_e(\hat L i_d + \hat\lambda_m)$$

### 1.3 Discrete PI with Back-Calculation Anti-Windup

$$u_k = K_p e_k + I_k + u^{ff}_k,\qquad \bar u_k = \mathrm{sat}(u_k)$$

$$I_{k+1} = I_k + T_s\left[K_i e_k + K_{aw}(\bar u_k - u_k)\right],\qquad K_{aw}\approx K_i/K_p$$

The dq voltage vector is limited to the linear SVPWM circle |v| ≤ V_bus/√3. Priority goes to v_d, and v_q receives the remainder:

$$v_q^{max} = \sqrt{(V_{bus}/\sqrt3)^2 - v_d^2}$$

### 1.4 SVPWM by Min-Max Zero-Sequence Injection

Inverse Clarke:

$$v_a = v_\alpha,\qquad v_b = -\tfrac12 v_\alpha + \tfrac{\sqrt3}{2}v_\beta,\qquad v_c = -\tfrac12 v_\alpha - \tfrac{\sqrt3}{2}v_\beta$$

Zero-sequence injection and duty cycles:

$$v_0 = -\tfrac12\big(\max(v_{abc}) + \min(v_{abc})\big),\qquad D_x = \tfrac12 + \frac{v_x + v_0}{V_{bus}}$$

This is mathematically identical to 7-segment SVPWM.

## 2. Velocity Estimation (Encoder PLL Observer)

Raw differentiation of a 14-bit encoder at 5 kHz quantizes velocity to 2π/16384 × 5000 ≈ 1.9 rad/s, which is too coarse. Use a type-2 tracking observer:

$$\varepsilon_k = \mathrm{wrap}_\pi(\theta_{m,k} - \hat\theta_k)$$

$$\hat\omega_{k+1} = \hat\omega_k + T_s K_{i,o}\,\varepsilon_k$$

$$\hat\theta_{k+1} = \hat\theta_k + T_s(\hat\omega_{k+1} + K_{p,o}\,\varepsilon_k)$$

Gains are K_{p,o} = 2ζω_o and K_{i,o} = ω_o². Use ω_o ≈ 2π·400 rad/s (more than 2.5× the velocity loop bandwidth) and ζ = 0.9.

The observer runs at the current-loop rate. It also supplies ω̂_e = p·ω̂ for the decoupling terms.
