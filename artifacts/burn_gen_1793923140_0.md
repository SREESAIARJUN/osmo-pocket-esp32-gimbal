# 3-Axis Gimbal FOC Control & Dual-IMU Sensor Fusion: Design Specification

I don't have the Job #42 hardware specification, so this design assumes typical gimbal parameters, listed in §0. Every assumption is a named constant in the code, so you can substitute your real values.

---

## 0. Assumed Plant & Timing

| Item | Assumed value |
|---|---|
| Motor | Gimbal BLDC, 12N14P (p = 7 pole pairs), R = 5.6 Ω, L = 2.4 mH (phase), K_t ≈ 0.08 N·m/A |
| Encoder | 14-bit absolute magnetic (AS5048A/MT6701 class), one per axis |
| IMU | 2× ICM-42688-P on the camera plate, SPI @ 24 MHz, gyro/accel ODR 8 kHz |
| MCU | Cortex-M4F/M7 with FPU (STM32G4/H7 class) |
| Gimbal order | Yaw (outer) → Roll → Pitch (inner, carries the camera and IMUs) |

**Loop rates.** Bandwidths are separated by ≥ 5× between successive loops.

| Loop | Rate | Target closed-loop bandwidth |
|---|---|---|
| Current (FOC, d/q PI) | 20 kHz (PWM-synchronous) | ~1.5 kHz |
| IMU acquisition and filtering | 8 kHz | — |
| Rate (velocity) loop | 4 kHz | ~150 Hz |
| Attitude (angle) loop + Mahony fusion | 1 kHz | ~20 Hz |

## 1. Field-Oriented Control (Inner Current Loop)

### 1.1 Electrical angle

$$\theta_e = p\,(\theta_m - \theta_{m,0}) \bmod 2\pi$$

Here θ_{m,0} is the encoder offset at which the d-axis aligns with phase A. It is found at commissioning by applying V_d with θ_e = 0 and reading the encoder.

### 1.2 Clarke transform (amplitude-invariant)

Assuming balanced currents, i_a + i_b + i_c = 0:

$$i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}(i_a + 2 i_b)$$

### 1.3 Park transform

$$\begin{bmatrix} i_d\\ i_q\end{bmatrix} = \begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix} i_\alpha\\ i_\beta\end{bmatrix}$$
