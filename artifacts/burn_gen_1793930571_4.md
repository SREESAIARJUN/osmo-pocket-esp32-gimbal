# FOC Motor Control and Dual-IMU Sensor Fusion for a 3-Axis Gimbal

I don't have a spec sheet for Job #37, so this design is built on the **explicit assumptions in §0**. Every tuning value is derived from parameters you can swap in. The equations and code are a complete reference design. Values marked **[VERIFY]** must be checked against your hardware or datasheets before flight.

---

## 0. Assumptions and Timing Architecture

| Item | Assumed value | Symbol |
|---|---|---|
| Motor | Gimbal BLDC, 12N14P (e.g., GBM2804-class) | $N_s=12,\ p=7$ pole pairs |
| Phase resistance / inductance | 5.6 Ω / 2.1 mH (line-to-neutral) | $R_s, L_s$ |
| Torque constant | 0.075 N·m/A | $K_t = \tfrac{3}{2}p\lambda_m$ |
| Axis inertia (motor + payload) | 4.0e-4 kg·m² | $J$ |
| Encoder | 14-bit absolute magnetic (MT6701/AS5048A class) | $\theta_m$ |
| MCU | STM32G4 @ 170 MHz, FPU | — |
| Bus voltage | 12 V | $V_{dc}$ |
| IMUs | 2 × ICM-42688-P on SPI, shared CLKIN | — |

**Loop rates** are kept multi-rate and synchronous to the PWM ISR:

| Loop | Rate | Bandwidth target |
|---|---|---|
| Current (FOC) | 20 kHz | $\omega_c = 2\pi\cdot 1500$ rad/s |
| IMU sampling | 8 kHz ODR, filtered then decimated to 4 kHz | — |
| Velocity (inertial rate) | 4 kHz | $\omega_v = 2\pi\cdot 80$ rad/s |
| Angle (attitude) | 1 kHz | $\omega_\theta = 2\pi\cdot 15$ rad/s |

The bandwidth separation between loops is at least 5×, so each inner loop looks like unity gain to the loop outside it.
