## 0. Assumptions and Timing Architecture

| Item | Value (replace with yours) |
|---|---|
| Motor | Gimbal BLDC (GBM2804-class), 12N14P, pole pairs p = 7 |
| Phase resistance R, inductance L | 5.6 Ω (line-to-neutral equivalent), 1.8 mH |
| Flux linkage λ_m | 0.0045 Wb (Kt = 1.5·p·λ_m ≈ 0.047 N·m/A) |
| Encoder | 14-bit magnetic (AS5048A / MT6701) on each motor shaft |
| IMUs | 2× ICM-42688-P on the camera plate, SPI @ 24 MHz |
| Axis order (base→camera) | Yaw (z) → Roll (x) → Pitch (y) |
| MCU | Cortex-M4F/M7 with single-precision FPU |

Each loop runs at a different rate:

```
20 kHz  PWM ISR      : ADC → Clarke/Park → id/iq PI → decoupling → SVPWM
 4 kHz  IMU DRDY ISR : 2×ICM read → per-IMU notch/LPF → fusion → Mahony
                       → angle P → Jacobian → velocity PI (+ anti-cog FF) → iq*
 4 kHz  (same ISR)   : dynamic notch retune from motor speed
  bg    main loop    : anti-cogging LMS learning, IMU health, telemetry
```

Loop bandwidths are spaced so each loop is about 5–10× slower than the one inside it:

- Current loop: 1.5–2 kHz (2–3 kHz is fine for gimbal torque fidelity).
- Velocity loop: about 150–250 Hz. It is limited by IMU group delay and structural modes.
- Angle loop: about 30–50 Hz.
