# 3-Axis Gimbal: FOC Motor Control, Anti-Cogging, and Dual-IMU Sensor Fusion

I don't have your project context for "Job #5", so this design rests on the assumptions below. Every assumption is a parameter in the code.

| Item | Assumption |
|---|---|
| MCU | Cortex-M4F/M7 (STM32G4/H7 class), single-precision FPU |
| Motors | 3× gimbal BLDC, 12N14P (e.g. GBM2804), 7 pole pairs |
| Position sensor | 14-bit magnetic encoder per axis (AS5048A / MT6701) |
| Current sensing | 2- or 3-shunt, sampled at PWM center |
| IMUs | 2× ICM-42688-P on the camera plate, SPI, shared CLKIN |
| Vibration source | Multirotor propellers, 80–400 Hz, plus frame modes |

## 1. Loop Architecture and Rates

```
            1 kHz                 4 kHz                       20 kHz
 θ_ref ─►[Angle P + FF]─ω_ref─►[Velocity PI-D]─τ─►(÷Kt)─iq*─►[Current PI dq + SVPWM]─► Motor
              ▲                     ▲                ▲   ▲            ▲
              │                     │      cogging FF┘   │            │ i_abc, θ_e
     attitude (Mahony, 4 kHz)  inertial rate (dual IMU, 8 kHz → filtered)   encoder
```

**Rate selection rule.** Each loop's crossover is at least 5–10× below the next-inner crossover, and each loop's sample rate is at least 10× its own crossover.

| Loop | Rate | Target crossover |
|---|---|---|
| Current | 20 kHz | ω_ci ≈ 2π·1.5 kHz |
| Velocity | 4 kHz | ω_cv ≈ 2π·60–120 Hz |
| Angle | 1 kHz | ω_cθ ≈ 2π·8–20 Hz |

**Key design point.** The velocity loop's feedback is the *inertial* rate of the camera, taken from the fused IMU gyro and projected onto the joint axis. It is not the encoder rate.

- This is what makes the gimbal reject base motion.
- The encoder is used only for commutation, cogging compensation, and joint-limit handling.
