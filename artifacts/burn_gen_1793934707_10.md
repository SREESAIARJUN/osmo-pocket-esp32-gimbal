# FOC Control Loop, Anti-Cogging Feedforward and Dual-IMU Fusion for a 3-Axis Gimbal

I don't have the specification for "Job #18," so I designed against the typical brushless-gimbal hardware listed in §0. Every hardware-specific value is a named constant, so you can substitute your real motor, encoder, MCU and mounting data. Values marked **⚠ verify** need checking against your datasheets or bench measurements before you power hardware.

## 0. Assumptions and Loop Architecture

| Item | Assumed value |
|---|---|
| Motor | Gimbal BLDC, 24N22P (p = 11 pole pairs), R = 5.6 Ω, L = 2.1 mH (phase), λ = 0.0118 V·s/rad (elec), Kt = 1.5·p·λ ≈ 0.195 N·m/A |
| Encoder | 14-bit absolute magnetic (AS5048A / MT6701 class), read over SPI every current-loop tick |
| Current sensing | Low-side shunts, 2-phase, ADC triggered at the PWM valley |
| MCU | STM32G4 / H7-class, FPU, 170+ MHz |
| Bus voltage | 12–16 V |
| IMUs | 2 × ICM-42688-P on the camera payload, ODR 8 kHz, ±2000 dps, ±16 g |

The control structure is a five-stage cascade. Each loop has roughly 5–10× more bandwidth than the loop outside it.

| Loop | Rate | Target bandwidth | Measured from |
|---|---|---|---|
| Current (d/q PI + decoupling) | 20 kHz | 1.5–2 kHz | Phase shunts, encoder angle |
| Cogging feedforward | 20 kHz | n/a (feedforward) | Encoder angle |
| Velocity / rate PI | 4 kHz | 150–250 Hz | Fused IMU gyro, projected onto the joint axis |
| Angle / attitude P(I) | 1 kHz | 15–30 Hz | Attitude estimate (dual IMU + Mahony) |
| IMU sampling & filtering | 8 kHz, decimated to 4 kHz | n/a | Two ICM-42688-P |

The gimbal stabilises the *camera* in inertial space. That is why the rate loop is closed on the payload gyro rather than on the encoder. The encoder is still used for commutation, for the cogging phase, and as a fallback rate source.
