## 0. Architecture Decisions and Assumptions

### 0.1 Partitioning

The STM32H743 should **not** commutate the motors directly. It is the flight controller running ArduPilot. Running four sensorless BLDC commutation loops at 48 kHz PWM with zero-crossing detection alongside the ArduPilot scheduler is not a supported ArduPilot configuration, and it would be a large real-time risk.

The proven partitioning is:

```
                    ┌──────────────────────────────┐
  RC / GPS / etc ──►│  STM32H743 @ 400 MHz         │
                    │  ArduPilot (ChibiOS)          │
                    │  Bi-dir DShot600 x4           │
                    └──┬──────┬──────┬──────┬──────┘
                       │M1    │M2    │M3    │M4   (single-wire, open-drain-ish, 3.3V)
                    ┌──▼──┐┌──▼──┐┌──▼──┐┌──▼──┐
                    │ESC  ││ESC  ││ESC  ││ESC  │  4x AT32F421 / STM32G071 running AM32
                    │MCU  ││MCU  ││MCU  ││MCU  │  (48 kHz complementary PWM, 6-step)
                    └──┬──┘└──┬──┘└──┬──┘└──┬──┘
                    3φ driver + 6x N-MOSFET per motor (24 FETs total)
```

## 1. Conduction Loss Model

### 1.1 Current Path in 6-Step with Complementary (Synchronous) PWM

During any 60° commutation sector, one phase is driven high and one is driven low. With complementary PWM:

- **During D·T_sw:** HS(A) and LS(B) conduct.
- **During (1−D)·T_sw:** LS(A) (synchronous rectifier) and LS(B) conduct.

Therefore **two FETs are always in the current path**, independent of duty cycle.
