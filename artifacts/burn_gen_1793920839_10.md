# 3-Axis Gimbal FOC Control and Dual-IMU Fusion: Design Specification and C++ Reference Implementation

I don't have the Job #59 requirements document, so this design uses typical brushless gimbal hardware. Every assumed value is in a configuration struct, so substitute your actual motor, encoder, and MCU parameters.

## 0. System Assumptions and Timing Architecture

| Item | Assumed value |
|---|---|
| MCU | STM32G474 (170 MHz, FPU, CORDIC), center-aligned PWM |
| Motors | Gimbal BLDC, 12N14P (pole pairs p = 7), R ≈ 5.6 Ω, L ≈ 2.2 mH, K_t ≈ 0.08 N·m/A |
| Encoder | 14-bit absolute magnetic (AS5048A / MT6701) on each joint |
| IMUs | 2× ICM-42688-P on the camera plate, on separate SPI buses, mounted at different lever arms |
| Kinematics | Yaw (z) → Roll (x) → Pitch (y), from base outward |

```
 20 kHz  PWM ISR : ADC currents → Clarke/Park → PI(d,q) → inv-Park → SVPWM   (per axis)
 8 kHz   IMU DRDY: dual ICM-42688 read → align → notch/LPF → fuse
 4 kHz   Rate loop : gyro-rate PI (camera frame) → J⁻¹ → iq_ref + cogging FF
 1 kHz   Attitude  : Mahony AHRS update → quaternion error → rate command
```

Choose loop rates so each loop's bandwidth is at least 5× slower than the loop inside it. The full delay chain (ADC → compute → PWM update) must be included in the margin calculations.
