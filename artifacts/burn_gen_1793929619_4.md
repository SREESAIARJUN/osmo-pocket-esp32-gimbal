## 0. Assumptions and Timing Architecture

| Item | Assumed value |
|---|---|
| Motor | Gimbal BLDC (e.g. GBM2804-class), 12N14P, so **p = 7 pole pairs**. R ≈ 10 Ω, L ≈ 4 mH, Kt ≈ 0.08 N·m/A |
| Position sensor | 14-bit magnetic encoder (AS5048A / MT6701) on the motor shaft |
| Current sense | 2 or 3 inline/low-side shunts, ADC sampled at PWM center |
| MCU | STM32G4 / H7-class Cortex-M4F/M7 with an FPU. All math is `float` |
| IMUs | 2× ICM-42688-P on the camera plate, SPI @ 24 MHz, gyro/accel ODR 8 kHz |

### Loop rates (time-scale separation ≥ 4–5×)

```
 20 kHz  : ADC → Clarke/Park → PI_d, PI_q → inv-Park → SVPWM        (current loop, BW ≈ 1.5–2 kHz)
  8 kHz  : IMU read (both) → AAF(on-chip) → notch → fusion          (sensor path)
  4 kHz  : Velocity PI (inertial rate) + cogging FF + accel FF       (BW ≈ 150–250 Hz)
  1 kHz  : Attitude estimator (Mahony) + angle P/PD loop             (BW ≈ 30–50 Hz)
```

### Control architecture

```
θ_ref ─►(+)─► C_θ ─►(+)─► C_ω ─►(+)─► i_q* ─► [FOC current loop] ─► motor ─► camera
        ▲−        ω_ff ▲−        ▲ i_ff(cog) + J·α_ref/Kt
        │              │
   θ̂ (Mahony)    ω̂_axis = ê_axisᵀ · ω_fused  (inertial rate from the IMUs, NOT the encoder)
```

Two design choices are worth calling out:

- **The encoder is used only for commutation** (electrical angle) and cogging indexing.
- **The velocity loop is closed on inertial rate.** That is what stabilizes the camera against base motion.
