# 3-Axis Gimbal: FOC Control Loops, Cogging Compensation, and Dual-IMU Fusion (Job #42)

I don't have a spec sheet for Job #42, so this design rests on the assumptions in §0. Every parameter is a named constant so you can substitute your real hardware values.

---

## 0. Assumptions

| Item | Assumed value |
|---|---|
| Motors | 3× gimbal BLDC, 12N14P (p = 7 pole pairs), R ≈ 5 Ω, L ≈ 2 mH |
| Rotor sensing | 14-bit absolute magnetic encoder per axis (AS5048A / MT6701) |
| Current sensing | 2-phase inline shunts |
| MCU | STM32G4 / H7 class with FPU |
| PWM / current loop | 20 kHz, center-aligned, SVPWM |
| IMUs | 2× ICM-42688-P on the camera plate, SPI, gyro/accel ODR 8 kHz |
| Inertial rate loop | 4 kHz (decimated from 8 kHz after filtering) |
| Attitude/angle loop | 1 kHz |
| Kinematics | Yaw (outer) → Roll → Pitch (inner): R = R_z(ψ) R_x(φ) R_y(θ) |

---

## 1. Loop Architecture

```
            1 kHz                   4 kHz                    20 kHz
 q_ref ─► [Attitude P + ω_ff] ─► [Inertial rate PI-D] ─► Jᵀ ─► [Σ cog FF] ─► [FOC current PI] ─► SVPWM
             ▲   (camera frame)       ▲  (camera frame)    (joint torques)          ▲
             │                        │                                             │
       [Mahony AHRS] ◄── [Dual-IMU fusion + notch/LPF] ◄── 2× ICM-42688-P      encoder θ_m, i_abc
```

- The **rate loop is closed on the camera-frame gyro**. This is inertial stabilization: base motion is rejected directly, without waiting for it to show up as an angle error.
