# 3-Axis Gimbal: FOC Control Loop and Dual-IMU Sensor Fusion (Job #10)

## 0. Design Assumptions

I don't have the Job #10 specification, so the design rests on the assumptions below. Every value is a single `constexpr` in the code. Replace them with your measured motor and plant data before closing the loops on hardware.

| Item | Assumed value |
|---|---|
| MCU | STM32G474 @ 170 MHz, FPU, 3× advanced timers, center-aligned PWM |
| Motors | Gimbal BLDC, 12N14P (p = 7 pole pairs), R = 5.6 Ω, L = 2.6 mH, K_t = 0.08 N·m/A |
| Axis inertia (with payload) | J = 1.5·10⁻⁴ kg·m² (pitch); scale for roll and yaw |
| Joint encoder | 14-bit magnetic (MT6701/AS5048), SPI, read every current cycle |
| IMUs | 2× ICM-42688-P on the payload plate, separate SPI buses, ODR 8 kHz |
| Supply | V_bus = 16.8 V (4S) |

**Loop rates**

| Loop | Rate | Purpose |
|---|---|---|
| PWM | 20 kHz | Switching frequency |
| Current (FOC) | 20 kHz | Torque control |
| IMU sampling, filtering, fusion | 8 kHz | Inertial rate and attitude |
| Velocity | 4 kHz | Inertial rate control |
| Angle | 1 kHz | Attitude control |

Velocity and angle feedback are **inertial**, from the payload IMUs. The encoder is used only for commutation, cogging-table indexing, the joint Jacobian, and encoder-rate fallback. This is what makes the gimbal a stabilizer rather than a position servo.
