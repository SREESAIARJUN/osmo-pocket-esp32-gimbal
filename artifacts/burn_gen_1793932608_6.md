# STM32H743 AIO + 4-in-1 ESC (Job #28): Loss Model, Thermal Analysis, DShot DMA Plan, Reference Netlist

## 0. Feasibility Verdict

**80 A burst per motor on a 20×20 mm nano AIO is not thermally or electrically credible.** The numbers below show why. I recommend one of these three options:

- Re-rate the board to roughly 35–45 A burst for 1 s and 25–30 A continuous.
- Move to a 30.5×30.5 mm or larger stack.
- Keep "80 A" only as a sub-100 ms peak spec with explicit test conditions.

**All component parameters are assumptions.** Replace them with datasheet values for the parts you actually select before using any figure for sign-off.

**Architecture assumption.** The H743 runs ArduPilot and generates DShot600. Each of the four ESC channels has its own small MCU (e.g., AT32F421 or STM32G071 running AM32/BLHeli_32), and that MCU generates the 48 kHz PWM. The H743 does not commutate the motors directly. If you intended the H743 to run field-oriented control (FOC) for all four motors, that is a fundamentally different (and not recommended) design. Tell me and I'll rework it.

## 2. Conduction Loss Model

**Commutation scheme.** Six-step trapezoidal drive with synchronous rectification. At any instant, one high-side FET and one low-side FET carry the phase current. Each FET carries current for 1/3 of the electrical period.

**High-side FET (PWM duty D)**

P_cond,HS = I_ph² · R_ds(T_j) · D / 3

**Low-side FET (static on, plus synchronous freewheel during (1−D) of the paired leg)**

P_cond,LS ≈ I_ph² · R_ds(T_j) · (1/3) · [1 + (1−D)] / 2 … simplified bound: ≤ I_ph² · R_ds / 3

**Worst-case conduction (D → 1, full-throttle burst)**

P_FET = 80² × 1.5 mΩ / 3 = **3.2 W per FET**

P_cond,ESC = 2 × I_ph² × R_ds = 2 × 6400 × 1.5e-3 = **19.2 W per motor**

P_cond,4in1 = **76.8 W**

**Thermal coupling of R_ds(on).** R_ds(on) rises with junction temperature:

R_ds(T_j) = R_ds,25 · [1 + α(T_j − 25)], with α ≈ 0.0065 /K

Iterate this together with the thermal model in §4 until T_j converges. If T_j does not converge, you are in thermal runaway.

**Copper and connector losses (often ignored, but significant here)**

- Total battery current is up to 4 × 80 × D_avg. Assuming roughly 0.8 equivalent, that is about **256 A** for full-throttle bursts on all four motors.
- At 0.3 mΩ for the pads, bus planes, and shunt: P = 256² × 0.3e-3 ≈ **19.7 W**.
- An XT60 connector (about 60 A continuous) and 12–14 AWG leads cannot support this.

## 3. Switching Loss Model at 48 kHz

**Hard-switching V–I overlap (high-side FET, per PWM period)**

P_sw = ½ · V_bus · I_ph · (t_r + t_f) · f_sw
= 0.5 × 25.2 × 80 × 20e-9 × 48e3 = **0.97 W**

This applies while the FET is PWM-ing (D < 1). It is maximal around D ≈ 0.5–0.9, where current is still high.

**Output capacitance (Coss) loss**

P_oss = Q_oss · V_bus · f_sw = 30e-9 × 25.2 × 48e3 = **0.036 W**

**Dead-time body-diode conduction (low side)**

P_dt = V_SD · I_ph · 2 · t_dead · f_sw = 0.8 × 80 × 200e-9 × 48e3 = **0.61 W**

**Reverse recovery (Qrr) loss**

P_rr = Q_rr · V_bus · f_sw. Assuming Q_rr ≈ 50 nC, this is about **0.06 W**.

**Gate drive (per FET; dissipated mostly in driver and gate resistor)**

P_g = Q_g · V_gs · f_sw = 60e-9 × 10 × 48e3 = **0.029 W**

**Per-ESC worst switching operating point (D ≈ 0.9)**

| Component | Loss |
|---|---|
| Active HS conduction (80² × 1.5e-3 × 0.9) | 8.64 W |
| Active LS conduction (path) | ≈ 9.6 W |
| HS switching | 0.97 W |
| Dead-time | 0.61 W |
| Qrr + Coss | ≈ 0.1 W |
| **Total** | **≈ 20 W per ESC → ≈ 80 W per 4-in-1** |

**Sensitivity.** Halving f_sw to 24 kHz saves only about 0.8 W per ESC. **Conduction dominates.** The lever is R_ds(on) and the number of parallel FETs, not frequency.

## 4. Thermal Model

### 4.1 Network

Node chain: T_j → R_θJC → T_case → R_θCB (solder + vias) → T_board → R_θBA (convection + radiation) → T_amb

| Parameter | Assumed value |
|---|---|
| R_θJC (PDFN 3×3) | ≈ 1.5 K/W |
| R_θCB, with ≥ 9 thermal vias Ø0.3 mm under pad | ≈ 3 K/W per FET |
| R_θBA, 20×20 board, 6-layer 2 oz, prop-wash ~5 m/s | ≈ 6–10 K/W (whole board) |
| C_th, board (≈ 4 g FR4/Cu + FETs) | ≈ 2.5 J/K |

### 4.2 Steady state at 80 W

ΔT_board = 80 × 8 ≈ **640 K**. This is physically impossible: there is **no continuous 80 A rating**.

**Maximum continuous dissipation** for T_board ≤ 100 °C at T_amb = 35 °C:

P_max = 65 / 8 ≈ **8 W total**

That corresponds to about **2 W per ESC**, or roughly **25 A per motor continuous** with these FETs:

I = √(2 / (2 × 1.5e-3)) ≈ 26 A

### 4.3 Burst (transient) analysis

Board heating rate, adiabatic approximation:

dT/dt ≈ P / C_th = 80 / 2.5 ≈ **32 K/s**

Single-pole response:

T(t) = T_0 + P · R_θBA · (1 − e^(−t/τ)), with τ = R_θBA · C_th ≈ 20 s

Results for a burst starting from a 60 °C board:

| Burst length | Board temperature |
|---|---|
| 0.5 s | ≈ 76 °C |
| 1 s | ≈ 91 °C |
| 2 s | ≈ 122 °C (exceeds MLCC and solder-reliability limits) |

**Junction rise above the board, per FET**

ΔT_j-board ≈ 3.2 W × (1.5 + 3) K/W ≈ **14 K**. Use the datasheet Z_θJC curve for pulses under 100 ms.

**Conclusion.** About 1 s at 80 A is survivable only from a cool start. Repeated bursts ratchet the temperature up. The firmware should enforce an I²t limit:

∫ I² dt ≤ (T_max − T_board) · C_th / (2 R_ds)

Implement this in the ESC firmware. Also monitor ESC temperature telemetry in ArduPilot via bi-directional DShot EDT or BLHeli telemetry.

### 4.4 Thermal mitigations, ranked

1. Parallel FETs (2 per switch) to halve conduction loss, or move to 5×6 packages. Neither fits on 20×20.
2. Use the lowest-R_ds(on) 30 V parts only if the board is limited to 4S.
3. Use a 6–8 layer board with 2 oz inner copper and filled, capped vias under the FET pads.
4. Mount a thermal pad or aluminum spreader to the frame.

## 5. ArduPilot Bi-directional DShot600 Timer/DMA Allocation (H743)

### 5.1 Constraints

- **DMAMUX routing.** The H743 has DMA1 and DMA2 (8 streams each) behind DMAMUX1, so any request can go to any stream. The limit is stream count, not fixed mapping.
- **Two DMA requests per timer.** ArduPilot DShot uses the timer's UP DMA (burst write to DMAR) for output. Bi-directional DShot additionally needs **input-capture DMA on the channel's own TIMx_CHy request** to read the eRPM reply.
- **Channel pairing.** ArduPilot pairs channels for capture: CH1 with CH2 and CH3 with CH4. Put BIDIR on the lower channel of each pair, or as the current docs specify; **verify against the ArduPilot hwdef documentation for your firmware version.**
- **Group rates.** All outputs on one timer share a protocol and rate. Keep the four motors on at most two timers, and keep them off timers used for LED/serial-LED or buzzer.
- **Reserved timers.** Avoid TIM2/TIM5 if the hwdef uses them for the system timer. ChibiOS on H7 typically uses TIM2 or TIM5 as the systick timer, so check `STM32_ST_USE_TIMER`.
- **DMA-safe memory.** DMA buffers must be in AXI SRAM or SRAM1–3, not DTCM. ArduPilot's allocator handles this.
