# STM32H743 AIO Nano FC + 4-in-1 ESC (Job #10): Architecture & Feasibility Analysis

## 0. Feasibility Finding

Before the derivations: **an 80 A per-motor burst rating on a nano (20×20 mm or 25.5×25.5 mm) AIO board is not thermally achievable.** Section 2 quantifies this. My recommendation is either:

- **(a)** Re-spec to about 80 A *total* (four motors at 20 A each), which is plausible for a nano AIO.
- **(b)** Keep 80 A per motor and move to a 30.5×30.5 mm or larger stacked ESC with a heatsink.

All math below is parametric, so you can rerun it with your actual MOSFET choice.

**Architecture note.** The H743 is the flight controller MCU. A 4-in-1 ESC still needs its own motor-control MCU(s) running AM32 or BLHeli_32, for example AT32F421 or STM32G071, either one per motor or a dual-core variant. The H743 commands those MCUs over bidirectional DShot600. It does not drive the gates directly.

## 1. Power Stage Loss Model (per motor, per half-bridge set)

### 1.1 Assumptions

| Parameter | Symbol | Value |
|---|---|---|
| Bus voltage (6S nominal) | V_bus | 22.2 V (25.2 V worst case) |
| Phase current (burst) | I | 80 A |
| PWM frequency | f_sw | 48 kHz |
| MOSFET (40 V, 3.3×3.3 class) | R_ds(on),25 | 1.0 mΩ |
| R_ds tempco | α | ≈ 0.0055 /K, so ×1.5 at 115 °C |
| Rise + fall time | t_r + t_f | 40 ns total at I = 80 A |
| Gate charge | Q_g | 60 nC @ 10 V |
| Body diode V_f / Q_rr | V_f, Q_rr | 0.8 V / 50 nC |
| Dead time | t_d | 100 ns per edge |
| Output capacitance | C_oss | 1.5 nF |

Scheme: trapezoidal 6-step with synchronous (complementary) PWM, so two FETs are always in the current path.

### 1.2 Conduction Loss

During the on-time the current flows through the high-side FET. During the off-time it freewheels through the synchronous low-side FET. Either way, two FETs carry I at all times.

$$R_{ds}(T_j) = R_{ds,25}\,[1+\alpha(T_j-25)]$$

$$P_{cond} = 2\,I^2\,R_{ds}(T_j)$$

At T_j = 115 °C, R_ds = 1.5 mΩ:

$$P_{cond} = 2 \times 80^2 \times 1.5\times10^{-3} = \mathbf{19.2\ W}$$

Because this depends on T_j, it is a positive feedback loop. Solve it iteratively alongside §2. If R_th is too high, the loop runs away.

### 1.3 Switching Loss (hard-switched edges)

$$P_{sw} = \tfrac12 V_{bus}\, I\,(t_r+t_f)\, f_{sw} = 0.5 \times 25.2 \times 80 \times 40\text{n} \times 48\text{k} = \mathbf{1.94\ W}$$

### 1.4 Secondary Losses

| Term | Formula | Value |
|---|---|---|
| Dead-time diode conduction | V_f · I · 2t_d · f_sw | 0.8·80·200n·48k = **0.61 W** |
| Reverse recovery | Q_rr · V_bus · f_sw | 50n·25.2·48k = **0.06 W** |
| C_oss | ½ C_oss V² f_sw | **0.02 W** |
| Gate drive (6 FETs, only 2 switching at PWM rate) | Q_g · V_gs · f_sw · 2 | 60n·10·48k·2 = **0.06 W** (dissipated in driver/R_g) |

### 1.5 Totals

| | Per motor | ×4 motors |
|---|---|---|
| Conduction | 19.2 W | 76.8 W |
| Switching + secondary | 2.7 W | 10.8 W |
| Copper/shunt (≈0.5 mΩ path) | 3.2 W | 12.8 W |
| **Total** | **≈25 W** | **≈100 W** |

**Key insight.** At this current level, conduction loss is about 77% of the total. Raising f_sw from 24 to 48 kHz only costs about 1 W per motor. f_sw is not your lever; R_ds(on) and copper area are.

## 2. Thermal Model

### 2.1 Lumped Transient (burst)

Single-node RC model:

$$\Delta T(t) = P\,R_{th}\left(1-e^{-t/\tau}\right),\quad \tau = R_{th} C_{th}$$

Nano AIO estimate:

- **Thermal mass:** board plus components ≈ 6 g at an effective c_p ≈ 0.7 J/g·K gives **C_th ≈ 4.2 J/K**.
- **Board-to-ambient resistance:** with prop wash at ~10 m/s over about 8 cm² of two-sided area, h ≈ 60 W/m²K, so **R_th ≈ 10 K/W**.
- **Time constant:** τ ≈ 42 s.

For short bursts (t ≪ τ), the rise is nearly adiabatic:

$$\frac{dT}{dt} \approx \frac{P}{C_{th}} = \frac{100}{4.2} \approx \mathbf{24\ K/s}$$

| Burst duration | ΔT_board | T_board (from 40 °C) |
|---|---|---|
| 1 s | 23 K | 63 °C |
| 3 s | 66 K | 106 °C |
| 5 s | 106 K | **146 °C → failure** |

### 2.2 Junction Rise Above the Board

Add R_th,jc + R_th,cb ≈ 2.5 K/W per FET. Each conducting FET dissipates about 10–12 W, so the junction sits **≈25–30 K above the local board**. At 3 s the junction is already near 135 °C. Factoring in the R_ds feedback from §1.2, the practical limit is **about 2 s at 4×80 A**.

### 2.3 Steady State (continuous)

T_amb = 40 °C and T_board,max = 100 °C give:

$$P_{max} = \frac{60}{10} = 6\text{ W total}$$

Since P ≈ 4 × 2I²R_ds,eff with R_ds,eff ≈ 2 mΩ including copper:

$$I_{cont} \approx \sqrt{\frac{6}{4\times 2\times 2\times10^{-3}}} \approx \mathbf{19\ A\ per\ motor}$$

This confirms recommendation **(a)**: a 20 A continuous / about 30–35 A 5 s burst per-motor rating is the honest spec for a nano AIO.

### 2.4 Design Levers (ranked)

1. **Use 0.6–0.7 mΩ FETs** in 5×6 packages. This cuts conduction loss by about 40%, but the packages may not fit on a nano board.
2. **Use 2 oz outer and 2 oz inner copper with via arrays** under the FET drains (0.3 mm vias at 0.6 mm pitch). This spreads heat into the full board.
3. **Add an NTC near the FETs** and have AM32 current-limit and temperature-derate based on it. This is mandatory.
4. **Keep f_sw at 24 kHz unless motor acoustics demand 48 kHz.** This saves about 1 W per motor.

## 3. Bidirectional DShot600: Timing & DMA Allocation

### 3.1 Timing Math

| Quantity | Value |
|---|---|
| Bit period | 1/600 kHz = 1.667 µs |
| Frame (16 bit) | 26.67 µs |
| Timer clock (H743 @ 400 MHz, APB timers) | 200 MHz |
| Ticks per bit | 200 MHz / 600 kHz ≈ 333 (ArduPilot computes prescaler/ARR automatically) |
| "1" / "0" duty | 75% / 37.5% of bit (inverted logic in bidir mode) |
| Turnaround before ESC reply | ≈ 30 µs |
| eRPM telemetry reply | 21 bits GCR at 5/4 × 600 kHz = 750 kbit/s, ≈ 28 µs |
| Full TX + RX cycle | ≈ 90 µs, so ≥ 8 kHz loop rate is feasible |

### 3.2 Pin / Timer Allocation (ArduPilot hwdef)

ArduPilot's bidirectional DShot convention is that **the BIDIR tag goes on one channel of each CH1/CH2 or CH3/CH4 pair**. The paired channel's DMA is used for input capture of the reply. All alternate functions below are AF2.

```
# Motors – TIM3 and TIM5, AF2 on all pins
PB0 TIM3_CH3 TIM3 PWM(1) GPIO(50) BIDIR
PB1 TIM3_CH4 TIM3 PWM(2) GPIO(51)
PA0 TIM5_CH1 TIM5 PWM(3) GPIO(52) BIDIR
PA1 TIM5_CH2 TIM5 PWM(4) GPIO(53)

# LED strip on a separate timer so it does not share a DMA group with motors
PA8 TIM1_CH1 TIM1 PWM(5) GPIO(54)

# Prioritise motor DMA
DMA_PRIORITY TIM3* TIM5* SPI1*
DMA_NOSHARE  TIM3_UP TIM5_UP SPI1*
```

Verify this against the current ArduPilot hwdef documentation and the `dma_resolver.py` output for your branch. The resolver output is the authoritative allocation.
