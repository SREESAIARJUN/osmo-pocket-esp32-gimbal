# 3-Axis Gimbal FOC Control and Dual-IMU Sensor Fusion Design (Job #58)

I don't have the Job #58 specification, so the design below rests on the stated baseline assumptions. Every assumption is a single constant in the code. Change them to match your hardware, then re-derive the gains with the formulas given.

---

## 0. Baseline Assumptions

| Item | Assumed value |
|---|---|
| Motors | Gimbal BLDC, 12N14P (7 pole pairs), R = 5.6 Ω, L = 2.1 mH, λ = 0.012 V·s/rad (per-phase, line-neutral) |
| Inverter | 3-phase, 16 V bus, 2 inline/low-side shunts per motor, 20 kHz center-aligned PWM |
| Rotor sensor | 14-bit absolute magnetic encoder per axis (AS5048A / MT6701 class) |
| IMUs | 2× ICM-42688-P on the camera plate, separate SPI buses, common FSYNC, ODR = 8 kHz |
| Gimbal order | Yaw (outer, z) → Roll (middle, x) → Pitch (inner, y) |
| MCU | Cortex-M7 / M4F with single-precision FPU |

**Loop rates (cascaded, with each loop ≥ 4–5× the bandwidth of the next loop out):**

| Loop | Rate | Closed-loop bandwidth |
|---|---|---|
| Current (d/q) | 20 kHz | ~1.5 kHz |
| Velocity (inertial rate from gyro) | 4 kHz | ~150 Hz |
| Angle (attitude) | 1 kHz | ~25 Hz |
| IMU filtering | 8 kHz | AAF ≈ 1 kHz |

> If your boards have **no current sensing** (common on cheap gimbals), run the current loop in voltage mode: v_q = R·i_q* + ω_e·λ. The cascaded velocity/angle design below still applies, with lower achievable bandwidth (~60 Hz velocity).

## 1. FOC Inner Current Loop

### 1.1 Transforms

Use the amplitude-invariant Clarke transform:

$$
i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}(i_a + 2 i_b),\qquad (i_c = -i_a - i_b)
$$

Park transform, with electrical angle θ_e = p·θ_m − θ_offset:

$$
\begin{bmatrix} i_d\\ i_q\end{bmatrix}=
\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}
\begin{bmatrix} i_\alpha\\ i_\beta\end{bmatrix}
$$
