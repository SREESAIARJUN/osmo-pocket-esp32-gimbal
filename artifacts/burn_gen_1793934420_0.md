# FOC Motor Control & Dual-IMU Sensor Fusion for a 3-Axis Gimbal

I don't have the specification for Job #43, so this design uses typical values for a camera gimbal: gimbal BLDC motors, 14-bit magnetic encoders, two ICM-42688-P IMUs on the camera plate, and an STM32G4/H7-class MCU. Every parameter is in one config struct, so you can substitute your real values without touching the algorithms.

## 0. System Architecture & Timing

```
                ┌──────────── 1 kHz ────────────┐ ┌──── 4 kHz ────┐ ┌──── 20 kHz ────┐
 θ_ref ──►(+)─► Angle P/PI ─►(+)──► ω_ref ─►(+)─► Velocity PI ─►(+)─► i_q* ─► Current PI ─► SVPWM ─► Motor
          ▲−                 ▲ ω_ff         ▲−                 ▲ i_ff(cog,accel)   (d/q, decoupled)
          │                                 │                  │
     θ_meas (fused attitude          ω_meas (notched,        θ_enc (14-bit encoder) ─► commutation
      → joint space)                  averaged dual gyro)
```

**Loop rates**

| Loop | Rate | Feedback | Bandwidth target |
|---|---|---|---|
| Current (d/q) | 20 kHz (PWM-synced ISR) | Phase shunts + encoder θₑ | ~1.5–2 kHz |
| Velocity | 4 kHz | Inertial gyro rate (dual IMU, filtered) | ~150–250 Hz |
| Angle / stabilization | 1 kHz | Fused attitude (Mahony) → joint error | ~20–40 Hz |
| IMU sampling | 8 kHz ODR, decimated to 4 kHz | — | — |

**Key design choice.** The velocity loop is closed on the **inertial gyro**, not the encoder derivative. This makes the gimbal reject base motion directly. The encoder is used only for commutation, cogging-table lookup, and joint-angle limits. Each successive loop should be at least 5× faster than the one it commands, so the inner loops look like unity gain to the outer ones.

## 1. FOC Current Loop

### 1.1 Transforms

Assume balanced phases, i_a + i_b + i_c = 0, with amplitude-invariant scaling. θₑ = p·θₘ + θ_offset, where p is the number of pole pairs.

**Clarke transform**

$$i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}(i_a + 2 i_b)$$

**Park transform**

$$\begin{bmatrix} i_d\\ i_q\end{bmatrix}=\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix} i_\alpha\\ i_\beta\end{bmatrix}$$

**Inverse Park transform**

$$v_\alpha = v_d\cos\theta_e - v_q\sin\theta_e,\qquad v_\beta = v_d\sin\theta_e + v_q\cos\theta_e$$

### 1.2 Plant Model (SPMSM, L_d ≈ L_q = L)

$$v_d = R i_d + L\dot i_d - \omega_e L i_q$$
$$v_q = R i_q + L\dot i_q + \omega_e L i_d + \omega_e \lambda_m$$
$$\tau = \tfrac32 p \lambda_m i_q = K_t\, i_q$$

### 1.3 Decoupled PI with Pole-Zero Cancellation

After the cross-coupling and back-EMF terms are fed forward, each axis is a first-order plant: 1/(Ls + R).

Choose the PI zero K_i/K_p = R/L. This cancels the plant pole, so the closed loop becomes a first-order system with bandwidth ω_c:

$$K_p = L\,\omega_c,\qquad K_i = R\,\omega_c\quad(\text{continuous}),\qquad K_i^{disc}=R\,\omega_c\,T_s$$

**Control laws**

$$v_d^* = \mathrm{PI}_d(i_d^*-i_d) - \omega_e L i_q$$
$$v_q^* = \mathrm{PI}_q(i_q^*-i_q) + \omega_e L i_d + \omega_e\lambda_m$$

**Constraints**
- Set i_d* = 0 (no field weakening is needed at gimbal speeds).
- Keep ω_c ≤ 2π·f_pwm/10 to keep phase margin despite the 1.5-sample PWM/computation delay.

### 1.4 Voltage Limiting & Anti-Windup

**Circular voltage limit**

$$|v| \le V_{dc}/\sqrt3 \quad (\text{SVPWM linear region})$$

When the limit is hit, give v_d priority (it holds the flux angle), then clamp v_q:

$$v_q^{max}=\sqrt{V_{max}^2 - v_d^2}$$

**Back-calculation anti-windup**, with gain K_aw ≈ 1/K_p:

$$I_{k+1} = I_k + K_i e_k + K_{aw}(u_{sat}-u_{unsat})$$

### 1.5 SVPWM via Min/Max Zero-Sequence Injection

This is equivalent to sector-based SVPWM but needs no branching.

$$v_{a,b,c} = \text{inverse Clarke}(v_\alpha,v_\beta),\qquad v_0 = -\tfrac12\big(\max(v_{abc})+\min(v_{abc})\big)$$
$$d_x = \tfrac12 + \frac{v_x + v_0}{V_{dc}}$$

## 2. Cascaded Velocity / Angle Control

### 2.1 Mechanical Plant per Axis

$$J\dot\omega = K_t i_q - B\omega - \tau_{cog}(\theta_m) - \tau_{dist}$$

### 2.2 Velocity Loop (PI + Feedforward)

The inner current loop is treated as unity gain (its bandwidth is at least 10× higher).
