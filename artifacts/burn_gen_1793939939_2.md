# 3-Axis Gimbal: FOC Control, Anti-Cogging Feedforward, and Dual ICM-42688-P Fusion

I don't have the Job #40 specification, so this design uses the stated assumptions below. Every parameter is a `constexpr` or a config struct, so you can retarget it without changing the structure.

---

## 0. Assumptions and Loop Architecture

| Item | Assumed value |
|---|---|
| MCU | STM32G4 / H7 class, Cortex-M4F/M7 with single-precision FPU |
| Motor | Gimbal BLDC (e.g. GM4108): 12N14P, so p = 7 pole pairs, R ≈ 10 Ω, L ≈ 3 mH |
| Encoder | 14-bit absolute magnetic encoder (AS5048A / MT6701), read every PWM cycle |
| Current sense | 2 low-side shunts (a voltage-mode fallback is provided) |
| IMUs | 2 × ICM-42688-P on the camera plate, SPI at 24 MHz, 8 kHz ODR, data-ready interrupt |

Loop rates:

```
 20 kHz  ── Current loop (FOC: Clarke/Park, PI on id/iq, SVPWM)       [ADC-triggered ISR]
  8 kHz  ── IMU read ×2, notch/LPF, rate fusion                      [IMU DRDY ISR]
  4 kHz  ── Velocity PI + cogging FF + accel FF  → iq*                [/5 of current ISR]
  1 kHz  ── Attitude filter, Jacobian, angle P(I) → ω*                [/20]
```

Bandwidth separation is at least 4–5× per cascade stage:

- ω_c ≈ 2π·2000 rad/s (current)
- ω_v ≈ 2π·150 rad/s (velocity)
- ω_θ
