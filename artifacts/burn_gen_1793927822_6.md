# STM32H743 Nano FC + 4-in-1 ESC (Job #42): Power-Stage Loss Model, Thermal Budget, and Bi-Directional DShot600 Timer/DMA Plan

## 0. Architecture Assumptions and Up-Front Findings

**Architecture.** The STM32H743 cannot run four sensorless BLDC commutation loops and act as an ArduPilot flight controller at the same time. This design therefore assumes a stacked architecture:

- **FC board:** STM32H743 running ArduPilot. It emits bi-directional DShot600.
- **4-in-1 ESC board:** four AM32 or BLHeli_32-class ESC MCUs (for example AT32F421 or STM32G071), with three half-bridges per motor.

**Operating point.**

| Parameter | Symbol | Value |
|---|---|---|
| Battery | V_bus | 6S, 25.2 V max |
| Burst phase current per motor | I | 80 A |
| PWM frequency | f_sw | 48 kHz |
| Commutation | | 6-step, synchronous rectification (complementary PWM) |
| MOSFET (representative 40 V, 3.3×3.3 DFN) | R_ds(on),25 | 1.5 mΩ |
| | Q_g | 40 nC |
| | Q_rr | 50 nC |
| | Q_oss | 30 nC |
| | t_r + t_f | 20 ns |
| | R_th,jc | 1.2 K/W |
| | V_SD | 0.8 V |
| Dead time | t_dt | 100 ns |
| Phase shunt | R_sh | 0.25 mΩ |

**Bottom line: 80 A per motor on a nano board is a ~1-second burst rating, not a continuous one.** Section 3 shows why. Please challenge the "80 A" requirement before layout begins.

## 1. Conduction Loss Model

### 1.1 Temperature-dependent on-resistance

```
R_ds(T_j) = R_ds,25 · [1 + α(T_j − 25)],   α ≈ 0.006 /K
R_ds(110 °C) = 1.5 mΩ · 1.51 = 2.27 mΩ
```

### 1.2 Per-channel conduction in 6-step synchronous mode

During any commutation sector, two phases conduct:

- **PWM-ed leg:** current alternates between the high-side (HS) switch (for duty D) and the low-side (LS) synchronous switch (for 1−D). Loss = D·I²R + (1−D)·I²R = I²R, independent of duty.
- **Return leg:** the LS switch is fully on. Loss = I²R.

```
P_cond,ch = 2 · I² · R_ds(T_j)
          = 2 · 6400 · 2.27e-3
          = 29.0 W            (at T_j = 110 °C)
```

### 1.3 Distribution across the six FETs

Each leg spends one-third of the electrical cycle PWM-ing, one-third as the solid low side, and one-third floating. The average loss per FET is therefore:

```
P_FET,avg ≈ P_cond,ch / 6 ≈ 4.8 W
```

The peak per sector is about 14.5 W in a single LS FET. This is the hot-spot device for short-term R_th,jc transients.

### 1.4 Shunt and copper losses

```
Shunt:              P_sh = I² · R_sh = 6400 · 0.25e-3 = 1.6 W per channel
Phase/bus copper:   assume 0.3 mΩ effective → ≈ 1.9 W per channel
```

## 2. Switching Loss Model at 48 kHz

Only the PWM-ed leg switches hard. Each term below is per channel.

| Term | Formula | Value |
|---|---|---|
| V–I overlap | ½·V·I·(t_r+t_f)·f = ½·25.2·80·20e-9·48e3 | 0.97 W |
| Reverse recovery | Q_rr·V·f = 50e-9·25.2·48e3 | 0.06 W |
| C_oss | ½·Q_oss·V·f | 0.02 W |
| Dead-time body diode | V_SD·I·2·t_dt·f = 0.8·80·2·100e-9·48e3 | 0.61 W |
| Gate drive (2 switching FETs) | 2·Q_g·V_gs·f = 2·40e-9·10·48e3 | 0.04 W (dissipated in driver/R_g) |
| **Total switching** | | **≈ 1.70 W** |

Sensitivity notes:

- Switching loss is about 6% of conduction loss. At 48 kHz this design is conduction-dominated, so choose FETs on R_ds(on) first and Q_g second.
- Dead time is the largest controllable switching term. Dropping from 100 ns to 50 ns saves 0.3 W per channel.

### 2.1 Total loss budget

| | Per channel | Board (×4) |
|---|---|---|
| Conduction (110 °C) | 29.0 W | 116 W |
| Switching | 1.7 W | 6.8 W |
| Shunt + copper | 3.5 W | 14 W |
| **Total** | **34.2 W** | **≈ 137 W** |

Delivered power is about 4 × 80 A × ~22 V ≈ 7 kW, so efficiency is about 98%. The efficiency is fine. The heat flux into a 20×20 mm board is the problem.

## 3. Thermal Model

### 3.1 Junction rise over the PCB

Using the peak-sector FET (14.5 W), with the single-pulse Z_th at about 1 ms around 0.3 K/W:

```
ΔT_jc ≈ 14.5 · 0.3   ≈ 4.4 K    (sector-length transient)
ΔT_jc ≈  4.8 · 1.2   ≈ 5.8 K    (averaged, steady)
```

The junction tracks the board closely, so **board heat capacity is the governing constraint.**

### 3.2 Lumped board thermal capacitance (20×20 mm, 6-layer, 2 oz, 1.6 mm)

| Element | Calculation | Heat capacity |
|---|---|---|
| Copper (≈50% fill) | 0.084 cm³ × 3.45 J/cm³K | 0.29 J/K |
| FR-4 | 0.64 cm³ × 1.9 J/cm³K | 1.22 J/K |
| 24 FETs + passives | | ≈ 0.15 J/K |
| **Total C_th** | | **≈ 1.66 J/K** |

### 3.3 Transient solution

For a first-order RC model, the board temperature during a burst is:

```
T(t) = T_0 + P · R_th,ba · (1 − e^(−t/τ)),   τ = R_th,ba · C_th
```

**Inputs:**

- R_th,ba (board to ambient) at prop-wash airflow is roughly 6 K/W for a nano board.
- This gives τ ≈ 6 × 1.66 ≈ 10 s.
- The burst duration is much shorter than τ, so treat it as adiabatic.

**Adiabatic rise rate and burst time:**

```
dT/dt ≈ P / C_th = 137 / 1.66 ≈ 83 K/s

t_burst (40 °C → 110 °C board) ≈ 70 / 83 ≈ 0.85 s
```

Because R_ds(on) rises with temperature, the loss term is itself temperature dependent. Coupling it in gives the full model:

```
C · dT/dt = 4[2I²R_25(1 + α(T − 25)) + P_sw + P_sh] − (T − T_a)/R_th
```

Solved numerically with this feedback included, the burst time is about 0.75 to 0.8 s.

### 3.4 Sustainable continuous current

With a 110 °C limit, 40 °C ambient and R_th = 6 K/W, the board can shed about 11.7 W total. That corresponds to roughly **20 to 22 A continuous per motor**.

| Board option | Burst at 80 A | Continuous per motor |
|---|---|---|
| Nano 20×20 | ≈ 0.8 s | ≈ 21 A |
| 30.5×30.5, 8-layer 2 oz | ≈ 2.2 s | ≈ 30 A |

### 3.5 Recommendations

1. **Firmware current limiting.** Set the AM32 current limit with an I²t model matching the equation above. Expose ESC temperature through BDShot EDT so ArduPilot can log or throttle it.
2. **Heat sinking.** Use thermal vias under every FET drain tab (0.3 mm, ≥ 9 per FET). An optional aluminium top plate adds about 1 J/K per gram... in practice, a 5 g plate roughly doubles burst time.

## 4. ArduPilot Bi-Directional DShot600 on STM32H743

### 4.1 Signal timing

| Item | Value |
|---|---|
| Bit rate | 600 kbit/s → T_bit = 1.667 µs |
| Frame | 16 bits ≈ 26.7 µs |
| ESC turnaround before reply | ≈ 30 µs |
| Telemetry reply | 21-bit GCR at 750 kbit/s ≈ 28 µs |
| Full cycle per frame | ≈ 90 µs, comfortably supporting up to 8 kHz loop rates |

**Timer clock:** TIM1/8 sit on APB2 and TIM2–5 on APB1, both clocked at 200 MHz with SYSCLK at 400 MHz. ArduPilot selects the prescaler so that ticks per bit are an integer; this is handled automatically.

**Capture requirement:** input capture must oversample the 750 kbit/s reply at least 3×. ArduPilot configures this automatically.

### 4.2 DMA model

ArduPilot BDShot uses two DMA paths:

- **Output:** the timer `TIMx_UP` DMA stream, burst-writing CCR registers for every channel on that timer.
- **Input:** a per-channel `TIMx_CHy` capture DMA stream, needed while receiving telemetry.
