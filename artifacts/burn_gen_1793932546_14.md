# FOC Motor Control and Dual-IMU Sensor Fusion for a 3-Axis Gimbal (Job #59)

## 0. Assumptions

I don't have the Job #59 spec sheet, so the design is built on the assumptions below. Every one of them is a constructor or `constexpr` parameter in the code, so you can change any of them without touching the math.

| Item | Assumption |
|---|---|
| Motors | 3× BLDC gimbal motors, 12N14P (`Np = 7` pole pairs), for example the GBM2804 class |
| Encoders | Absolute magnetic encoder per axis (AS5048A or MT6701 class, 14-bit) |
| MCU | Cortex-M4F/M7 with an FPU (STM32G4/H7 class) |
| IMUs | 2× ICM-42688-P on the camera plate, mounted with a 180° rotation about Z relative to each other, on separate SPI buses |
| Gimbal order | Yaw (outer) → Roll → Pitch (inner, carries the camera) |

Loop rates:

| Loop | Rate | Rate symbol |
|---|---|---|
| Current (FOC) | 20 kHz | `T_i = 50 µs` |
| Velocity | 4 kHz | `T_v = 250 µs` |
| Angle / attitude | 1 kHz | `T_a = 1 ms` |
| IMU sampling | 8 kHz ODR, FIFO-drained and decimated to the 4 kHz velocity loop | — |

The design separates loop bandwidths by at least 4–5× at every level so that each inner loop looks like unity gain to the loop around it.

## 1. Field-Oriented Control (Innermost Loop)

### 1.1 Plant model

PMSM equations in the rotor dq frame, with `ω_e = N_p·ω_m`:

```
v_d = R·i_d + L_d·di_d/dt − ω_e·L_q·i_q
v_q = R·i_q + L_q·di_q/dt + ω_e·L_d·i_d + ω_e·λ_m

τ_m = (3/2)·N_p·[λ_m·i_q + (L_d − L_q)·i_d·i_q]  ≈  K_t·i_q,   K_t = (3/2)·N_p·λ_m
```

Gimbal motors are surface-mount (`L_d ≈ L_q = L`) with high resistance (5–15 Ω). That makes `i_d* = 0` optimal: there is no reluctance torque to exploit.
