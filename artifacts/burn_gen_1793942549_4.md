# 3-Axis Gimbal: FOC, Cascaded Control, Anti-Cogging and Dual-IMU Vibration Rejection

I don't have the Job #32 specification, so this design uses the stated assumptions below. Every value marked **[ASSUMED]** is a parameter you can replace without changing the structure.

---

## 0. Assumptions and Timing Architecture

| Item | Value |
|---|---|
| MCU | STM32G474 (Cortex-M4F, 170 MHz, single-precision FPU) **[ASSUMED]** |
| Motors | 3× gimbal BLDC, 12N14P (Ns=12 slots, Np=14 poles, pole pairs p=7), R≈5 Ω, L≈2 mH **[ASSUMED]** |
| Encoders | 14-bit magnetic absolute encoders, one per joint (e.g. AS5048A/MT6835) |
| IMUs | 2× ICM-42688-P on the camera plate, SPI at 24 MHz, ODR 8 kHz, both on a shared external CLKIN (RTC mode) |

### Loop rates

| Loop | Rate | Bandwidth target |
|---|---|---|
| Current (FOC) | 20 kHz (PWM-synchronous) | ωc ≈ 2π·1.5 kHz |
| Anti-cogging feedforward | 20 kHz (inside the FOC ISR) | n/a |
| IMU acquisition and filtering | 8 kHz | n/a |
| Velocity (rate) | 4 kHz | ωv ≈ 2π·150 Hz |
| Angle (attitude) | 1 kHz | ωθ ≈ 2π·25 Hz |

Each loop has a bandwidth roughly 5–10× lower than the loop inside it. This separation is what justifies designing each loop as if its inner loop were an ideal unity-gain block.
