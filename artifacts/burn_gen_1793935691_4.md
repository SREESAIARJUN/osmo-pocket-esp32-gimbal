# 3-Axis Gimbal Control Design: FOC Cascade, Anti-Cogging Feedforward, and Dual ICM-42688-P Fusion

I don't have a spec for "Job #19", so the design rests on the assumptions in §0. Every equation is parametric. Replace the numbers with your hardware values and the derivations still hold.

---

## 0. Assumptions and Timing Architecture

| Item | Assumed value |
|---|---|
| MCU | STM32G4 / H7 class, FPU, 170+ MHz |
| Motors | Gimbal BLDC, 12N14P (pole pairs p = 7), R ≈ 5–15 Ω, L ≈ 2–5 mH |
| Joint encoder | 14-bit magnetic (AS5048A / MT6701), one per joint |
| Current sensing | 2- or 3-shunt, sampled center-aligned |
| IMUs | 2 × ICM-42688-P on the camera plate, SPI, 8 kHz ODR |
| Kinematic order | Base → **Yaw (z)** → **Roll (x)** → **Pitch (y)** → camera |

The loops run at these rates:

| Loop | Rate | Trigger |
|---|---|---|
| Current (FOC) | 20 kHz | PWM-center ADC ISR |
| IMU filtering and rate loop | 8 kHz | IMU data-ready interrupt (DRDY → DMA) |
| Attitude / angle loop | 1 kHz | Decimated from the 8 kHz task |
| Cogging adaptation | 1 kHz | Background, gated |

Each loop's bandwidth is at least 5× lower than the loop inside it. This keeps the loops nearly decoupled, so each can be designed treating the inner loop as ≈1 (unity gain).
