# FOC Control Loop and Dual-IMU Sensor Fusion for a 3-Axis Gimbal

I don't have the Job #14 specification, so this design states its assumptions explicitly. Each assumption is marked **[A]**. Replace them with your actual motor, encoder, MCU and mechanical data before tuning.

---

## 0. System Architecture and Assumptions

| Item | Assumed value |
|---|---|
| **[A]** Motors | 3× BLDC gimbal motors (e.g. GBM4108-class): 24N22P (N_s = 24 slots, p = 11 pole pairs), R ≈ 5–15 Ω, L ≈ 2–5 mH |
| **[A]** Encoders | 14-bit absolute magnetic encoder per joint (AS5048A / MA730 class) |
| **[A]** MCU | Cortex-M4F/M7 with FPU, 3 independent PWM timers, synchronized ADC |
| **[A]** Kinematics | Yaw (outer) → Roll (middle) → Pitch (inner, camera) |
| **[A]** IMUs | Two ICM-42688-P on the camera plate, SPI, 8 kHz ODR, rigidly mounted at known lever arms r₁, r₂ |

### Loop rates (time-scale separation ≥ 5× between loops)

```
                    ┌──────────────── 1 kHz ────────────────┐ ┌──── 4 kHz ────┐ ┌──── 20 kHz ────┐
 q_ref ──► attitude error ──► inertial-rate cmd ──► J⁻¹(θ) ──► ω_j,ref ─► Velocity PI ─► i_q,ref ─► Current PI ─► SVPWM
             ▲ (quat)                                              ▲            + cogging FF        ▲ i_d,i_q
             │                                                     │            + accel FF          │
       Dual-IMU fusion (8 kHz in → 1 kHz attitude)           encoder ω̂ (PLL)                 ADC + encoder θ_e
```

Some gimbal drivers run voltage-mode without current sensing. The design below assumes current sensing. Section 2.4 gives the voltage-mode fallback.
