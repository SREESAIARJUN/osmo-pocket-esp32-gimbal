## 0. Architecture Clarification and Assumptions

### 0.1 Architectural correction

The H743 should not commutate the motors. ArduPilot has no BLDC commutation or FOC stack. The correct partition is:

```
[STM32H743 FC, ArduPilot] --(4x Bidir DShot600, 1-wire each)--> [4x ESC MCU running AM32/BLHeli_32]
                                                                    |
                                                          [3-ph gate driver] -> [6 MOSFETs] -> motor
```

The H743 generates DShot600 frames and decodes the eRPM telemetry that each ESC returns on the same wire. Each ESC channel has its own MCU, which performs 48 kHz PWM and 6-step BEMF commutation. This document assumes an **AT32F421K8U7 running AM32**, chosen for mature 48 kHz support and well-documented open firmware.

### 0.2 Form-factor reality check

The math in §3 shows that 80 A per channel burst is **not achievable on a 20×20 mm "nano" board**. This document therefore targets a **30.5×30.5 mm mounting pattern (≈36×36 mm board)** for the ESC. If 20×20 is a hard requirement, the honest burst rating is roughly 35–45 A.

## 1. Conduction Loss Model

### 1.1 Six-step current paths with synchronous rectification

Each phase leg cycles through four 60°-pair intervals per electrical revolution:

- **High (120°):** the high-side (HS) FET conducts for duty D; the low-side (LS) FET conducts for (1−D) as the synchronous freewheel path.
- **Low (120°):** the LS FET conducts 100%.
- **Floating (2 × 60°):** the leg is off and the phase is used for BEMF sensing.
