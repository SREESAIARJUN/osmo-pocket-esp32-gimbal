# FOC Motor Control and Dual-IMU Sensor Fusion for a 3-Axis Gimbal

I don't have the project files or specification for Job #47. This design therefore rests on the assumptions in §0. Every parameter that depends on your hardware is a named constant, so you can substitute your real values.

---

## 0. Assumptions and Loop Architecture

| Item | Assumed value |
|---|---|
| Motor | Gimbal BLDC, 12N14P (pole pairs `p = 7`, slots `Ns = 12`), R ≈ 5–15 Ω, L ≈ 1–3 mH |
| Rotor sensor | 14-bit absolute magnetic encoder (AS5048A / MT6701 class), read at the current-loop rate |
| Current sense | 2 or 3 low-side shunts. If you have none, see the "voltage-mode" note in §1.4. |
| IMUs | 2 × ICM-42688-P on the camera plate, SPI, gyro/accel ODR 8 kHz, mounted symmetrically about the payload centre |
| MCU | Cortex-M4F/M7 with FPU (STM32G4/H7 class) |

**Loop rates and bandwidths**

| Loop | Rate | Target bandwidth |
|---|---|---|
| Current (d/q PI) | f_c = 20 kHz (ISR synced to PWM centre) | ~1.5–2 kHz |
| Velocity (PI, gyro feedback) | f_v = 4 kHz | 80–150 Hz |
| Angle (P + feedforward, attitude feedback) | f_θ = 1 kHz | 15–30 Hz |
| IMU acquisition, notch filtering, fusion | 8 kHz → decimated to 4 kHz | — |
| Attitude estimator (Mahony) | 1 kHz | — |

Each outer loop's bandwidth should be at least 4–5× below the inner loop's bandwidth (bandwidth separation).

**Feedback sources**

- The **velocity loop uses the inertial gyro rate**, projected onto the motor axis. This is what produces stabilisation.
- The encoder is used for **commutation and anti-cogging only**.
