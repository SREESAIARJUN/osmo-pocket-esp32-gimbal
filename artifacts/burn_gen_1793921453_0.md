# 3-Axis Gimbal: FOC Control Loop and Dual-IMU Sensor Fusion (Job #58)

I don't have the Job #58 spec sheet, so this design is built on the assumptions in §0. Every motor- and board-specific number is a named constant you can change. Equations come first, then a complete embedded C++17 implementation. It uses no heap, no exceptions, and single-precision math, and targets a Cortex-M4F/M7-class MCU.

---

## 0. Assumptions and Timing Architecture

| Item | Assumed value |
|---|---|
| Motor | Gimbal BLDC, 12N14P (pole pairs `p = 7`), R ≈ 5 Ω, L ≈ 2 mH, K_t ≈ 0.08 N·m/A |
| Encoder | 14-bit absolute magnetic (AS5048A / MT6701 class) over SPI |
| Driver | 3-phase, inline or low-side shunts, V_bus = 12–16 V |
| IMUs | 2 × ICM-42688-P on the camera platform, SPI, gyro ODR 8 kHz |
| Payload inertia | J ≈ 2×10⁻⁴ kg·m² per axis, to be identified per axis |

**Loop rates and bandwidths:**

```
PWM / current loop   f_i = 20 kHz   (ADC-triggered ISR)        ω_ci ≈ 2π·1.5 kHz
IMU fusion + rate    f_v =  4 kHz   (IMU data-ready, ODR 8k÷2) ω_cv ≈ 2π·100 Hz
Angle loop           f_θ =  1 kHz                               ω_cθ ≈ 2π·20 Hz
Cogging LMS          runs in the velocity loop, very small μ
```

**Feedback signals.** Rate feedback is the *inertial* camera rate from the fused gyros, projected onto each motor axis. This is what makes a stabilizer reject base motion. The encoder is used for commutation, cogging compensation, and the joint-angle kinematics.
