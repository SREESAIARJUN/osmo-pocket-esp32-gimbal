# 3-Axis Gimbal: FOC Control, Anti-Cogging Feedforward, and Dual ICM-42688-P Fusion

I don't have the Job #11 spec sheet, so this design rests on the assumptions in §0. Every motor- and board-specific value is a named constant, so you can substitute your real numbers.

---

## 0. Assumptions and Loop Architecture

| Item | Assumed value |
|---|---|
| MCU | STM32G474 (170 MHz, FPU, CORDIC), center-aligned PWM |
| Motors | 3× gimbal BLDC, 12N14P (p = 7 pole pairs), R ≈ 5 Ω, L ≈ 2 mH, Kt ≈ 0.08 N·m/A |
| Encoder | 14-bit magnetic (AS5048A / MT6701) on each motor shaft |
| Current sensing | 2-shunt low-side, sampled at PWM center |
| IMUs | 2× ICM-42688-P on camera plate, SPI @ 24 MHz, 8 kHz ODR |

### Loop rates

| Loop | Rate | Ts | Target bandwidth |
|---|---|---|---|
| Current (FOC) | 20 kHz | 50 µs | ω_c = 2π·1500 rad/s |
| Velocity | 4 kHz | 250 µs | ω_v = 2π·150 rad/s |
| Angle | 1 kHz | 1 ms | ω_θ = 2π·25 rad/s |
| IMU fusion | 8 kHz in, 4 kHz out | | |
| AHRS | 1 kHz | | |

Keep each outer bandwidth at most 1/5 to 1/10 of the inner one, so the inner loop looks like unity gain to the outer loop.

### Signal flow per axis

```
θ_ref ─►(Angle P + FF)─► ω_ref ─►(Velocity PI)─► i_q* ─(+ i_cog,ff)─►(Current PI d/q)─► SVPWM ─► Motor
            ▲                        ▲                                          ▲
       θ_cam (AHRS)          ω_cam (IMU gyro, axis-projected)            i_abc, θ_e (encoder)
```

Using the inertial gyro rate for the velocity loop has two benefits. It is far less noisy than a differentiated encoder, and it rejects base motion directly, which is the whole point of a stabilizer.
