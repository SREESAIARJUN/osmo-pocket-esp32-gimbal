# Job #44: 3-Axis Gimbal FOC Control and Dual ICM-42688-P Sensor Fusion

I don't have the Job #44 hardware spec, so this design uses the assumptions in §0. Every hardware-specific number is a named constant, so you can change it in one place. Register addresses and AAF table values are from my reading of the ICM-42688-P datasheet (DS-000347). **Verify them against your datasheet revision before flashing.**

---

## 0. Assumptions and Timing Architecture

| Item | Assumed value |
|---|---|
| MCU | STM32G4 @ 170 MHz, FPU, center-aligned PWM |
| Motors | Gimbal BLDC, 12N14P (p = 7 pole pairs), R = 5.6 Ω, L = 2.2 mH, K_t ≈ 0.10 N·m/A |
| Encoder | 14-bit absolute magnetic (AS5048A / MT6701), SPI |
| Topology | Yaw (outer, z) → Roll (middle, x) → Pitch (inner, y) |
| IMU-P | ICM-42688-P on the camera plate (payload attitude) |
| IMU-B | ICM-42688-P on the base/handle (disturbance feedforward, cross-check) |

| Loop | Rate | Ts | Target bandwidth |
|---|---|---|---|
| Current (FOC) | 20 kHz | 50 µs | ~1.5–2 kHz |
| Encoder PLL / velocity | 4 kHz | 250 µs | ~150–200 Hz |
| Angle / stabilization | 1 kHz | 1 ms | ~30–40 Hz |
| IMU ODR | 8 kHz (gyro), 1 kHz (accel) | | |

Each loop is set to roughly 5–10× the bandwidth of the loop outside it.

## 1. FOC Inner Current Loop

### 1.1 Transforms

Use amplitude-invariant Clarke with i_a + i_b + i_c = 0:

$$i_\alpha = i_a,\qquad i_\beta = \frac{i_a + 2i_b}{\sqrt3}$$

Park transform, with θ_e = p·θ_m − θ_offset:

$$\begin{bmatrix}i_d\\ i_q\end{bmatrix}=\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix}i_\alpha\\ i_\beta\end{bmatrix}$$

The inverse Park transform is the transpose.
