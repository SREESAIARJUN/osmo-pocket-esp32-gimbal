# FOC Control Loop and Sensor Fusion for a 3-Axis Gimbal (Job #29)

I don't have the Job #29 specification, so this design uses the assumptions below. Every parameter is a named constant, so you can substitute your real hardware values.

| Item | Assumed value |
|---|---|
| Motor | Gimbal BLDC, 12N14P (p = 7 pole pairs). R = 5.6 Ω, L = 2.1 mH, K_t = 0.085 N·m/A |
| Position sensor | 14-bit magnetic encoder (AS5048A / MT6701), used for commutation and joint angle |
| IMUs | **IMU-P** on the payload (camera) provides the stabilization feedback. **IMU-B** on the base/handle provides the vibration reference and disturbance feedforward. Both are ICM-42688-P on separate SPI buses. |
| MCU | STM32G4 / H7 class with a single-precision FPU |
| Loop rates | Current (FOC): 20 kHz. Velocity: 4 kHz. Angle/attitude: 1 kHz. IMU ODR: 8 kHz. |
| Joint order | Yaw (base) → Roll → Pitch (payload) |

## 1. Architecture

```
            ┌────────── 1 kHz ──────────┐ ┌──── 4 kHz ─────┐ ┌──────── 20 kHz ────────┐
 θ_ref ──►(+)─► P_θ ─(+)─► ω_ref ─►(+)─► PI_ω ─(+)─► i_q,ref ─► PI_i (d,q) + decoupling ─► SVPWM ─► Motor
          ▲         ▲ ω_ff         ▲          ▲ i_q,cog(θ_m)                 ▲ θ_e (encoder)
          │         │              │          │ (anti-cogging FF)            │
   attitude (Mahony on IMU-P)   ω_fb = payload gyro         i_abc (shunts)
          │                        │ (AAF → LPF → dynamic notch)
          └── IMU-P ───────────────┘
                 IMU-B ──► notch frequency tracker (ANF) ──► notch center f̂_v
                 IMU-B ──► base-rate disturbance feedforward ──► ω_ff
```

In a gimbal, the velocity loop is closed on the payload inertial rate (gyro), not on the encoder rate. That rate loop is what rejects base motion. The encoder is used for commutation, joint kinematics, and the cogging phase.
