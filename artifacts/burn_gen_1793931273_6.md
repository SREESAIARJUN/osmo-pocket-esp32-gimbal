# 3-Axis Gimbal Control Core: FOC, Cascaded Control, Anti-Cogging, Dual-IMU Vibration Rejection

I don't have the original Job #11 spec, so this design states its assumptions explicitly (§0). Every parameter that depends on your hardware is a named constant, so you can retarget it.

---

## 0. Assumptions and Architecture

| Item | Assumed value | Notes |
|---|---|---|
| MCU | STM32G4 / H7 class, FPU, 170+ MHz | Code is portable C++17. No heap, no exceptions. |
| Motors | Gimbal BLDC, 12N14P (p = 7 pole pairs), R ≈ 5–15 Ω, L ≈ 1–3 mH | Example: GBM2804-class |
| Position sensor | 14-bit absolute magnetic encoder (AS5048A / MT6701) on each joint | |
| Current sensing | 2- or 3-shunt, low-side, sampled at PWM center | |
| IMUs | 2 × ICM-42688-P on the camera plate, SPI @ 24 MHz, 8 kHz ODR | Different mounting orientations and positions |
| Joint order | Base → Yaw (Z) → Roll (X) → Pitch (Y) → camera | |

**Loop rates (multi-rate, synchronous to PWM):**

```
PWM / current loop (FOC)      : 20 kHz   (ADC-triggered ISR)
Encoder PLL + anti-cogging    : 20 kHz   (inside current ISR)
IMU read + vibration filters  :  8 kHz   (IMU DRDY → DMA → ISR)
Velocity loop (inertial rate) :  4 kHz
Attitude fusion + angle loop  :  1 kHz
Cogging LMS adaptation        :  1 kHz   (background, gated)
```

**Bandwidth separation rule.** Each inner loop needs at least 5× the bandwidth of the loop outside it:

- Current loop: ω_c ≈ 2π·1.5 kHz
- Velocity loop: ≈ 2π·150 Hz
- Angle loop: ≈ 2π·15–25 Hz

## 1. Field-Oriented Control (Current Loop)

### 1.1 Transforms

**Clarke transform** (amplitude-invariant, with i_a + i_b + i_c = 0):

$$
i_\alpha = i_a,\qquad i_\beta = \frac{1}{\sqrt3}(i_a + 2 i_b)
$$
