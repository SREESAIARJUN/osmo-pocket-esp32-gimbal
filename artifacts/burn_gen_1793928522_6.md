# 3-Axis Gimbal FOC Control Loop and Dual-IMU Sensor Fusion: Design and C++ Implementation

I don't have the Job #28 specification, so the design below states every hardware assumption. All parameters live in config structs, so you can substitute your real values without touching the algorithms. Verify the ICM-42688-P register values against your datasheet revision before flashing.

---

## 0. Assumptions and Loop Architecture

| Item | Assumed value |
|---|---|
| Motors | 3 × gimbal PMSM (e.g., 12N14P, GBM2804-class): p = 7 pole pairs, R ≈ 5 Ω, L ≈ 2 mH, K_t ≈ 0.08 N·m/A |
| Encoder | 14-bit absolute magnetic encoder per joint (AS5048A/MT6701) |
| MCU | Cortex-M4F/M7 with FPU (STM32G4/H7). Center-aligned PWM, ADC triggered at PWM center |
| IMUs | 2 × ICM-42688-P on the camera plate, on separate SPI chip-selects |
| Joint order | Base → yaw (ψ, z) → roll (φ, x) → pitch (θ, y) → camera |

**Loop rates and bandwidth separation.** Each outer loop is set at least 4–10× slower than the loop inside it:

```
 IMU fusion + attitude loop   1 kHz    ω_att ≈ 2π·8 Hz
 Velocity loop + cogging FF   4 kHz    ω_v   ≈ 2π·60 Hz
 Current (FOC) loop          20 kHz    ω_c   ≈ 2π·1.5 kHz
 IMU sampling (ODR)           8 kHz    (decimated with notch filtering → 1 kHz)
```

```
 q_ref ─►[Attitude P]─ω_cmd(cam)─►[J⁻¹]─►(+)─►[Vel PI]─►(+)─►[iq PI]─►[invPark]─►[SVPWM]─►Motor
             ▲                            ▲ q̇_meas     ▲ iq_ff (anti-cogging, angle FF)
             │                       J⁻¹·ω_gyro         │
        [Mahony]◄──[Notch/LPF]◄──[Dual-IMU fusion]◄─ICM#1, ICM#2      encoder θ_m ─► θ_e = p·θ_m − θ_off
```

## 1. Field-Oriented Current Loop (20 kHz)

### 1.1 Transforms (amplitude-invariant)

**Clarke transform.** This assumes balanced phases, i_a + i_b + i_c = 0:

$$i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}(i_a + 2 i_b)$$
