# Job #25: 3-Axis Gimbal FOC Control and Dual-IMU Sensor Fusion

## 0. Assumptions

Job #25 itself was not specified, so the design is parameterized around a typical gimbal stack. Adjust the constants in `config.hpp` to match your hardware.

| Item | Assumed value |
|---|---|
| MCU | STM32G474 class, Cortex-M4F at 170 MHz, single-precision FPU |
| Motors | Gimbal BLDC (GBM2804-class), 12N14P, so pole pairs p = 7 |
| Motor parameters | Phase resistance R ≈ 5.0 Ω, phase inductance L ≈ 2.0 mH, torque constant K_t ≈ 0.035 N·m/A |
| Encoder | 14-bit absolute magnetic encoder (AS5048A / MT6701), read over SPI every current cycle |
| Current sense | 2-shunt or 3-shunt sensing, sampled at the PWM center |
| IMUs | 2 × ICM-42688-P on the camera plate, ODR 8 kHz, ±2000 dps, ±16 g |
| Gimbal joint order | Base → Yaw (z) → Roll (x) → Pitch (y) → camera |

### Loop-rate hierarchy

Each loop should run at least 5× faster than the bandwidth of the loop outside it.

| Loop | Rate | Closed-loop bandwidth |
|---|---|---|
| Current (FOC), executed in the PWM ISR | 20 kHz | ~1.5 kHz |
| IMU acquisition + filtering | 8 kHz → decimated to 4 kHz | — |
| Velocity | 4 kHz | ~150 Hz |
| Attitude (angle) | 1 kHz | ~25 Hz |
| Attitude estimation (Mahony) | 1 kHz | — |

## 1. FOC Current Loop

### 1.1 Transforms

Electrical angle from mechanical angle:

$$\theta_e = p\,(\theta_m - \theta_{\text{offset}}) \mod 2\pi$$

**Clarke transform** (amplitude-invariant, using $i_a+i_b+i_c=0$):

$$i_\alpha = i_a,\qquad i_\beta = \frac{1}{\sqrt3}(i_a + 2i_b)$$

**Park transform:**

$$\begin{bmatrix}i_d\\ i_q\end{bmatrix}=\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix}i_\alpha\\ i_\beta\end{bmatrix}$$

**Inverse Park transform:**

$$v_\alpha = v_d\cos\theta_e - v_q\sin\theta_e,\qquad v_\beta = v_d\sin\theta_e + v_q\cos\theta_e$$
