## 0. Assumptions and Architecture

| Item | Assumed value |
|---|---|
| MCU | STM32G4 / H7-class, single-precision FPU, about 170 MHz |
| Motors | Gimbal BLDC, 12N14P (pole pairs p = 7), for example GBM2804 class: R ≈ 5–10 Ω, L ≈ 1–3 mH |
| Rotor sensor | 14-bit absolute magnetic encoder (AS5048A / MT6701) per axis |
| Current sensing | 2 in-line or low-side shunts per motor |
| IMU-P | ICM-42688-P on the **payload** (camera plate). This is the feedback sensor. |
| IMU-B | ICM-42688-P on the **base** (handle or drone side, before the dampers). This is the disturbance-reference sensor. |
| IMU ODR | 8 kHz gyro and accel, on-chip AAF enabled, read via SPI and FIFO |
| Joint order | Base → **Yaw** (z) → **Roll** (x) → **Pitch** (y) → camera |

### Loop rates (time-scale separation of at least 4× between loops)

```
 20 kHz  ── Current (FOC) loop   : Clarke/Park, PI d/q, decoupling, SVPWM       ω_c ≈ 2π·1500 rad/s
  4 kHz  ── Velocity loop        : PI on payload inertial rate + cogging FF     ω_v ≈ 2π·120  rad/s
  1 kHz  ── Angle loop           : P(+I) on attitude error → rate command       ω_θ ≈ 2π·25   rad/s
  8 kHz  ── IMU pipeline         : AAF → notch bank → LPF → fusion (Mahony)
```

### Role of the two IMUs

- **IMU-P (payload)** provides feedback: inertial rate for the velocity loop and attitude for the angle loop.
- **IMU-B (base)** serves as a disturbance reference in two ways:
  1. **Base-rate feedforward.** The motors counter-rotate the joints *before* the payload sees the disturbance.
  2. **Adaptive (NLMS) cancellation** of base-correlated linear vibration in the payload *accelerometer*. This keeps the attitude reference clean.

> **Design rule:** Never adaptively cancel the payload *gyro* against the base gyro. The correlated component is real payload rotation, which is exactly what the loop must correct. Removing it would blind the controller. Vibration on the payload gyro is handled by notch and low-pass filters only.
