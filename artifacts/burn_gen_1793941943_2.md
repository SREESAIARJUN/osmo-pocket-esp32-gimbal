# FOC Control Loop and Sensor Fusion Design for a 3-Axis Gimbal

I don't have the Job #28 specification, so this design uses the stated assumptions below. Each one is a single named constant in the code, so you can change it without touching the math.

## 0. Assumptions and Rate Plan

| Item | Assumed value |
|---|---|
| Motors | 3× gimbal BLDC, 12N14P (pole pairs p = 7), R ≈ 5 Ω, L ≈ 2 mH, Kt ≈ 0.05 N·m/A |
| Position sensor | 14-bit magnetic encoder per joint (e.g., AS5048/MT6701) |
| IMUs | 2× ICM-42688-P on the camera plate, SPI |
| Kinematic chain | base → yaw (z) → roll (x) → pitch (y) → camera |
| Bus voltage | 12–16 V |

| Loop | Rate | Target bandwidth |
|---|---|---|
| Current (FOC) | 20 kHz | ω_c = 2π·1500 rad/s |
| IMU sampling and filtering | 8 kHz ODR | — |
| Velocity (inertial rate) | 4 kHz | ω_v = 2π·150 rad/s |
| Attitude (angle) | 1 kHz | ω_θ = 2π·20 rad/s |

**Bandwidth separation rule:** ω_c ≥ 5–10·ω_v and ω_v ≥ 5–8·ω_θ. This keeps each inner loop approximately unity gain from the outer loop's point of view, so the loops can be tuned independently.

## 1. Field-Oriented Control (Current Loop)

### 1.1 Transforms

**Clarke transform** (amplitude-invariant, assuming i_a + i_b + i_c = 0):

$$i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}(i_a + 2 i_b)$$

**Park transform**, with electrical angle θ_e = p·θ_m − θ_offset:

$$\begin{bmatrix}i_d\\ i_q\end{bmatrix}=\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix}i_\alpha\\ i_\beta\end{bmatrix}$$

**Inverse Park** is the transpose of that matrix.

### 1.2 Plant Model (Surface PMSM, L_d = L_q = L)

$$L\dot i_d = v_d - R i_d + \omega_e L i_q,\qquad L\dot i_q = v_q - R i_q - \omega_e L i_d - \omega_e\psi_m$$

where ψ_m = Kt / (1.5·p) and the motor torque is τ = 1.5·p·ψ_m·i_q = Kt·
