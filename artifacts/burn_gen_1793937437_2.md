# 3-Axis Gimbal: FOC Motor Control and Dual-IMU Sensor Fusion

I don't have the original "Job #0" specification, so this design is built on the assumptions listed in §0. Every assumption is a named constant, so you can retune for your hardware without restructuring the code.

---

## 0. Assumptions and Timing Architecture

| Item | Value |
|---|---|
| MCU | Cortex-M4F/M7 with FPU (STM32G474 / H743 class) |
| Motors | 3× gimbal BLDC, 12N14P (pole pairs p = 7), R = 5.6 Ω, L = 2.2 mH (line-neutral) |
| Inverter | 3-phase, 24 V bus, inline/low-side current sensing on 2 phases |
| Encoder | 14-bit magnetic (AS5048A / MT6701), mechanical angle |
| IMUs | 2× ICM-42688-P on separate SPI buses, mounted on the camera platform |

The control system runs as four nested loops, each at a different rate:

| Loop | Rate | Ts | Closed-loop bandwidth |
|---|---|---|---|
| Current (FOC) | 20 kHz | 50 µs | ω_c ≈ 2π·1500 rad/s |
| Velocity | 4 kHz | 250 µs | ω_v ≈ 2π·150 rad/s |
| Angle | 1 kHz | 1 ms | ω_θ ≈ 2π·25 rad/s |
| IMU fusion / AHRS | 8 kHz ODR → 1 kHz AHRS | 125 µs / 1 ms | n/a |

Each loop's bandwidth is roughly 10× its outer neighbour (ω_c ≈ 10 ω_v, ω_v ≈ 6 ω_θ). This is the standard cascade design rule: it lets each outer loop treat the inner loop as a unity gain.

## 1. Field-Oriented Control (Inner Current Loop)

### 1.1 Coordinate Transforms

The electrical angle is derived from the mechanical encoder angle:

$$\theta_e = p\,(\theta_m - \theta_{\text{off}}) \bmod 2\pi$$

where θ_off is found at calibration by driving d-axis current at θ_e = 0 and reading the encoder.

**Clarke transform** (amplitude-invariant, using i_a + i_b + i_c = 0):

$$i_\alpha = i_a,\qquad i_\beta = \frac{1}{\sqrt3}(i_a + 2 i_b)$$

**Park transform** (stationary to rotating frame):

$$\begin{bmatrix} i_d\\ i_q\end{bmatrix}=\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix} i_\alpha\\ i_\beta\end{bmatrix}$$

The inverse Park transform is the transpose of this matrix.

### 1.2 Motor Model in the dq Frame (Surface PMSM, L_d = L_q = L)

$$v_d = R i_d + L\dot i_d - \omega_e L i_q$$
$$v_q = R i_q + L\dot i_q + \omega_e L i_d + \omega_e \lambda_m$$
$$\tau_e = \tfrac32 p \lambda_m i_q = K_t i_q$$

### 1.3 Current PI Controller with Decoupling

The cross-coupling and back-EMF terms are cancelled by feedforward:

$$v_d^* = \text{PI}_d(i_d^* - i_d) - \omega_e L i_q$$
$$v_q^* = \text{PI}_q(i_q^* - i_q) + \omega_e (L i_d + \lambda_m)$$

After decoupling, each axis is the first-order plant 1/(Ls + R). Choosing the PI zero to cancel the plant pole (K_i/K_p = R/L) gives the closed loop ω_c/(s + ω_c):

$$\boxed{K_p = L\,\omega_c,\qquad K_i = R\,\omega_c}$$

With the assumed motor this gives K_p = 20.7 V/A and K_i = 52 800 V/(A·s).

**Voltage limiting.** The command is clamped to the linear SVPWM circle, |v_dq| ≤ V_bus/√3. The d-axis gets priority:

$$v_q \le \sqrt{V_{\max}^2 - v_d^2}$$

**Gimbal motors without current sensing.** Many gimbal motors are wound for high resistance and run in voltage mode, with current estimated from the model:

$$v_q^* = R\,i_q^* + \omega_e\lambda_m$$

The code supports this via `CurrentMode::VoltageModel`.
