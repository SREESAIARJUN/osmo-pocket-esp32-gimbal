# STM32H743 FC + 4-in-1 ESC Nano Stack (Job #21): Power-Stage, Thermal, and Bidirectional-DShot Architecture

## 0. Feasibility Finding

**An 80 A per-motor burst on a 20×20 mm nano stack is thermally bounded to about 1–2 seconds.** The sustainable continuous current is about 28–32 A per motor. The math below shows why. Treat "80 A" as a short-burst rating, and enforce it in firmware with current limiting and thermal derating, or the board will fail in the field.

Also note the architectural split:
- The **STM32H743 is the flight controller**. It generates DShot.
- Each ESC channel runs its own commutation MCU (AM32 or BLHeli_32 class, e.g. AT32F421 or STM32G071). That MCU produces the 48 kHz PWM.

The H743 never touches gate drive.

## 2. Conduction Loss Model

**Commutation model.** Trapezoidal (6-step) commutation with complementary, synchronous-rectified PWM is assumed. At every instant, motor current flows through exactly two conducting channels in series, one in each active leg. This holds regardless of duty cycle D, because the high-side FET and its complementary low-side FET share the current over the PWM period.

**Temperature-dependent resistance:**

$$R_{ds}(T_j) = R_0\left[1+\alpha(T_j-25)\right],\quad \alpha\approx0.006/\text{K} \Rightarrow R(125^\circ C)=2.4\ \text{m}\Omega$$

**Per motor:**

$$P_{cond,motor} = I^2 \cdot 2R_{ds}(T_j) = 6400 \times 0.0048 = \mathbf{30.7\ W}$$

**Per FET** (6 FETs share the losses evenly over an electrical revolution):

$$P_{cond,FET} = \frac{I^2 R_{ds}}{3} = \mathbf{5.1\ W}$$

**All four motors:** 123 W.

Add PCB copper loss. A 2 oz, 8-layer, about 10 mm path gives roughly 0.3 mΩ per phase, which adds about 2 W per motor at 80 A.

## 3. Switching Loss Model at 48 kHz

Only the PWM'd leg hard-switches. The low-side FET commutates softly (ZVS through the body diode).

| Term | Equation | Value |
|---|---|---|
| V–I overlap | ½·V·I·(t_r+t_f)·f_sw = ½·25.2·80·20e-9·48e3 | 0.97 W |
| Dead-time diode conduction | V_f·I·2t_dt·f_sw = 0.8·80·400e-9·48e3 | **1.23 W** |
| Reverse recovery | Q_rr·V·f_sw | 0.05 W |
| C_oss discharge | ½·C_oss·V²·f_sw | 0.02 W |
| Gate drive (2 switching FETs) | 2·Q_g·V_drv·f_sw | 0.03 W (driver-side) |
| **Total switching, per motor** | | **≈ 2.3 W** |

**Design insight:** dead-time diode loss exceeds hard-switching loss. Reducing dead time from 200 ns to 100 ns saves about 0.6 W per motor. Where the AM32 hardware supports it, tune dead time to the minimum safe value. The 48 kHz choice adds only about 7% to total losses, so the frequency is justified for quieter, smoother low-throttle operation.

**Totals:**
- Per motor: 30.7 + 2.0 + 2.3 ≈ **35 W**
- All four motors: **≈ 140 W**

## 4. Thermal Model

### 4a. Burst (adiabatic) limit: board heat capacity

| Mass | Calculation | Heat capacity |
|---|---|---|
| Copper: 20×20 mm × 8 layers × 70 µm ≈ 224 mm³ ≈ 2.0 g | × 0.385 J/g·K | 0.77 J/K |
| FR4 ≈ 1.5 g | × 1.1 J/g·K | 1.65 J/K |
| 24 FETs + passives ≈ 1 g (mixed) | | ≈ 0.6 J/K |
| **Total** | | **C_th ≈ 3.0 J/K** |

$$\frac{dT}{dt}=\frac{P}{C_{th}}=\frac{140}{3.0}\approx \mathbf{47\ K/s}$$

Starting at 40 °C, the board reaches 110 °C in about **1.5 s** with all four motors at 80 A. A single motor at 80 A alone heats at about 12 K/s, which allows roughly 5–6 s.

### 4b. Junction rise over board (transient)

A short-pulse Z_th(j-pcb) of about 2.5 K/W at 1 s (DFN on a 2 oz pad with vias) gives:

$$\Delta T_{j-b} = 5.5 \times 2.5 \approx 14\ \text{K}$$

**Peak condition:** T_j ≈ T_board + 14 K. Keep T_board ≤ 110 °C so that T_j ≤ 125 °C.

### 4c. Steady-state (continuous) limit

- **Convective:** h ≈ 100 W/m²K under prop wash. Two-sided area is 8×10⁻⁴ m², giving G ≈ 0.16 W/K, or **R_θ(b-a) ≈ 6.2 K/W**.
- **Power budget:** allowing ΔT = 70 K (40 → 110 °C) gives P_max ≈ 11 W. Adding about 30% for conduction into the motor wires and frame gives **≈ 15 W**.

$$15 = 4\left(2I^2R + P_{sw}\right) \Rightarrow I_{cont} \approx \mathbf{28\text{–}30\ A\ per\ motor}$$

This matches what commercial nano stacks actually sustain. It confirms the 80 A figure is a burst rating only.

### 4d. Firmware enforcement

- Set the AM32 current limit to about 35 A continuous.
- Use the ESC NTC to drive linear derating from 100 °C to 120 °C.
- In ArduPilot, monitor `ESC_TLM` temperature via bidirectional-DShot EDT. Set `MOT_BAT_CURR_MAX` and enable `BATT_*` failsafes accordingly.

## 5. Bidirectional DShot600: Timing and ArduPilot Timer/DMA Allocation

### 5a. Timing

| Item | Value |
|---|---|
| Bit time | 1/600 kHz = 1.667 µs |
| Output frame | 16 bits = 26.7 µs (inverted logic for bidirectional mode) |
| Turnaround | ≈ 30 µs |
| ESC reply | 21-bit GCR at 5/4 × 600 kHz = 750 kbaud → 28 µs |
| Total transaction | ≈ 90 µs |

The total supports loop rates up to about 8 kHz.

### 5b. Timer selection

The H743's DMAMUX lets any DMA1/DMA2 stream serve any request, so stream conflicts are rarely the problem. The real constraints are:
- **Use non-complementary channels.** The N outputs cannot do input capture.
- **Put all 4 motors on one advanced timer** to minimize DMA streams and keep frames synchronized.
