# 3-Axis Gimbal FOC Control & Dual-IMU Sensor Fusion: Design Specification

## 0. Assumptions and Architecture

I have no details for "Job #25", so I designed this around a typical brushless camera-gimbal stack. Every parameter marked **[MEASURE]** must be identified on your hardware before you trust the gains.

| Item | Assumed value |
|---|---|
| MCU | STM32G4 / H7 class (FPU, 3 advanced timers, ≥3 ADC channels per axis) |
| Motors | Gimbal BLDC, 12N14P (pole pairs p = 7), R ≈ 5–15 Ω, L ≈ 1–3 mH **[MEASURE]** |
| Rotor sensor | 14-bit absolute magnetic encoder per axis (AS5048A / MT6701 class) |
| IMUs | 2× ICM-42688-P on the **camera plate**, mounted symmetrically about the rotation centre (§5.2), SPI at 24 MHz |
| Gimbal kinematics | Yaw (outer, base) → Roll → Pitch (inner, camera) |
| PWM | 25 kHz center-aligned, ADC sampled at the PWM valley |

### Loop-rate hierarchy

Each loop should have about 5–10× more bandwidth than the loop outside it.

| Loop | Rate | Closed-loop bandwidth |
|---|---|---|
| Current (d/q PI) | 25 kHz | 1.5–2.5 kHz |
| IMU sample + filtering | 8 kHz (ODR) | — |
| Rate (velocity) PI + cogging feedforward | 4 kHz | 60–120 Hz |
| Attitude (angle) P/PI | 1 kHz | 10–20 Hz |
| Attitude estimator (Mahony) | 1 kHz (gyro integrated at 4 kHz) | — |

### Signal flow

```
 setpoint q_ref ─► [Attitude P/PI] ─ω_cam_ref─► [J⁻¹(θ)] ─θ̇_ref─► [Rate PI]─┬─► iq_ref ─► [Current PI + decoupling] ─► SVPWM
       ▲                ▲                                       ▲          │        ▲
       │         q̂ (Mahony)                        ω_joint (IMU rate      + iq_cog(θm) (anti-cogging FF)
       │                ▲                           projected + encoder PLL)
       │      Dual ICM-42688 → HW AAF/notch → lever-arm cancel → fusion → dynamic notch → LPF
```

## 1. FOC Core Equations

### 1.1 Electrical angle

$$\theta_e = p\,(\theta_m - \theta_{0}) \bmod 2\pi$$

θ₀ is the encoder offset. Find it by applying a d-axis voltage V_d with θ_e = 0, letting the rotor settle, and recording θ_m.
