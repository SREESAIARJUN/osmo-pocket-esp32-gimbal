# Gimbal FOC Control and Dual-IMU Sensor Fusion: Design Specification

> **Assumptions.** I don't have the original Job #37 specification, so I've assumed a typical brushless camera gimbal. Each axis uses an outrunner PMSM (for example 12N14P, 7 pole pairs) with a 14-bit absolute magnetic encoder (AS5048A/MT6701 class), inline or low-side shunt current sensing, and an STM32G4/H7-class MCU with a single-precision FPU. Two ICM-42688-P IMUs are rigidly mounted on the camera plate. All motor parameters are placeholders to be replaced with measured values.

---

## 1. System Architecture and Timing

| Loop | Rate | Input | Output |
|---|---|---|---|
| Current (FOC) | 20 kHz (PWM-synchronous ADC) | i_a, i_b, θ_e | v_α, v_β to SVPWM |
| IMU sampling, filtering, fusion | 8 kHz (data-ready ISR / DMA) | 2× gyro, 2× accel | ω_cam, q_cam |
| Velocity | 4 kHz | ω_ref, ω_meas | i_q,ref |
| Angle / stabilization | 1 kHz | q_ref, q_cam, joint angles | ω_ref per joint |
| Cogging adaptation | 4 kHz (inside velocity task) | i_q,fb, θ_m | harmonic weights |

Signal chain:

```
q_ref ─►[Angle P + FF]─► ω_joint,ref ─►[Velocity PI]─► iq_fb ─(+)─► iq_ref ─►[Current PI + decoupling]─► SVPWM ─► Motor
                ▲                          ▲                 ▲ iq_ff (cogging)          ▲ id,iq
         q_cam (Mahony)           ω_joint (IMU→joint map         [Clarke/Park]
                ▲                  + encoder rate blend)
   [Dual ICM-42688-P → AAF → notch → align/fuse]
```

Rule of thumb for loop bandwidths: each outer loop should be at least 4–5× slower than the loop inside it. A typical set is ω_c ≈ 2π·1.5 kHz, ω_v ≈ 2π·80 Hz, and ω_θ ≈ 2π·15 Hz.

## 2. FOC Current Loop

### 2.1 Transforms (amplitude-invariant)

**Clarke transform**, assuming i_a + i_b + i_c = 0:

$$i_\alpha = i_a,\qquad i_\beta = \frac{i_a + 2 i_b}{\sqrt3}$$

**Park transform**, with θ_e = p·θ_m − θ_offset:

$$\begin{bmatrix} i_d\\ i_q\end{bmatrix}=\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix} i_\alpha\\ i_\beta\end{bmatrix}$$

**Inverse Park transform:**

$$v_\alpha = v_d\cos\theta_e - v_q\sin\theta_e,\qquad v_\beta = v_d\sin\theta_e + v_q\cos\theta_e$$

### 2.2 Plant model and decoupling

The surface-PM machine model in the rotating frame is:

$$v_d = R i_d + L\dot i_d - \omega_e L i_q,\qquad v_q = R i_q + L\dot i_q + \omega_e L i_d + \omega_e\lambda_m$$

With the decoupling feed-forward terms

$$v_d^{ff} = -\omega_e L i_q,\qquad v_q^{ff} = \omega_e L i_d + \omega_e\lambda_m$$

each axis reduces to a first-order RL plant:

$$G_i(s)=\frac{1}{Ls+R}$$

### 2.3 PI design by pole–zero cancellation

Use the controller C(s) = K_p + K_i/s with:

$$K_{p,i}=L\,\omega_c,\qquad K_{i,i}=R\,\omega_c\;\Rightarrow\; \frac{i}{i^*}=\frac{\omega_c}{s+\omega_c}$$

Two practical constraints:

- **Computation and PWM delay.** The total delay is T_d ≈ 1.5·T_s, so keep ω_c ≤ 1/(4·T_d). At 20 kHz this limits ω_c to about 2π·1.06 kHz.
- **Delay-compensated angle.** Use θ_e,comp = θ_e + 1.5·ω_e·T_s in the inverse Park transform.

**Discrete form with back-calculation anti-windup** (T_s = PWM period):

$$u_k = K_p e_k + I_k,\quad \bar u_k = \text{sat}(u_k),\quad I_{k+1}=I_k + K_i T_s e_k + K_{aw}(\bar u_k-u_k),\quad K_{aw}=\frac{K_i}{K_p}T_s$$
