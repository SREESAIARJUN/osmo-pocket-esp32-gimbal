# 3-Axis Gimbal FOC Control & Dual-IMU Sensor Fusion (Job #32)

## 0. Assumptions

I don't have the Job #32 specification, so this design uses the parameters below. Every one of them is a single constant in `GimbalConfig.hpp`, so you can substitute your real values without touching the algorithms.

| Item | Assumed value |
|---|---|
| MCU | STM32G474 @ 170 MHz, single-precision FPU, CORDIC available |
| Motors | 3 × GM4108-class outrunners: 24N22P (N_s = 24 slots, pole pairs p = 11), R = 10 Ω, L = 3 mH, J_rotor+load ≈ 2e-4 kg·m² |
| Encoders | 14-bit absolute magnetic encoder (AS5048A / MT6701) per axis, read over SPI at 20 kHz |
| IMUs | IMU-A: ICM-42688-P on the camera plate (payload). IMU-B: ICM-42688-P on the handle/base. |
| Gimbal order | base → yaw (z) → roll (x) → pitch (y) → camera |
| Loop rates | Current loop 20 kHz · encoder PLL 20 kHz · velocity loop 4 kHz · angle loop + attitude estimator 1 kHz · IMU ODR 8 kHz |

## 1. Current Loop (Innermost, 20 kHz)

### 1.1 Transforms

**Clarke transform** (amplitude-invariant, assumes i_a + i_b + i_c = 0):

$$i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}(i_a + 2i_b)$$

**Park transform**, with electrical angle θ_e = p·θ_m − θ_off:

$$\begin{bmatrix} i_d\\ i_q\end{bmatrix}=\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix} i_\alpha\\ i_\beta\end{bmatrix}$$

**Delay-compensated angle.** The PWM update takes effect about 1.5 samples after the current is sampled. The angle used for the inverse Park transform is therefore advanced:

$$\hat\theta_e = \theta_e + \omega_e\,(1.5\,T_s)$$

### 1.2 Plant and PI Gains

The dq-axis plant is:

$$L\frac{di_{d}}{dt} = v_{d} - R i_{d} + \omega_e L i_{q},\qquad L\frac{di_q}{dt} = v_q - R i_q - \omega_e L i_d - \omega_e\lambda_{pm}$$
