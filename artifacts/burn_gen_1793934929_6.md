# FOC Control Loop and Dual-IMU Sensor Fusion for a 3-Axis Gimbal

I don't have the original Job #42 specification, so this design states its assumptions explicitly. Every parameter is a named constant. Substitute your actual hardware values before tuning.

---

## 0. Assumptions and System Architecture

| Item | Assumed value |
|---|---|
| Motors | 3 × gimbal BLDC, 12N14P (pole pairs p = 7, slots Nₛ = 12), R ≈ 5–15 Ω, L ≈ 2–5 mH |
| Position sensor | 14-bit absolute magnetic encoder per joint (AS5048A / MT6701 class) |
| MCU | STM32G4 / H7 class with FPU, center-aligned PWM, synchronous ADC sampling |
| Current loop | 20 kHz, triggered from the PWM underflow ISR |
| Velocity loop | 4 kHz |
| Angle loop + attitude fusion | 1 kHz |
| IMUs | 2 × ICM-42688-P on separate SPI buses, gyro and accel ODR 8 kHz |
| Joint order | Yaw (base) → Roll → Pitch (camera) |

**Dual-IMU interpretation.** The design assumes the two IMUs are mounted in different places:

- **IMU-P** sits on the payload (camera) and provides the feedback signal.
- **IMU-B** sits on the base (handle or airframe) and provides the vibration reference and the disturbance feedforward.

This is the configuration that makes "vibration rejection" work, because the base IMU measures the disturbance before it reaches the camera. If both IMUs are instead co-located on the payload, §5.5 gives the redundant-averaging variant.
