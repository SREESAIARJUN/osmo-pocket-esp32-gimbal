# 3-Axis Gimbal: FOC Motor Control and Dual-IMU Sensor Fusion

I don't have any prior context for "Job #8," so this design rests on the stated assumptions below. Each one is parameterized, so you can substitute your real values without changing the structure.

---

## 0. Assumptions and Timing Architecture

| Item | Assumed value |
|---|---|
| Motors | 3× gimbal BLDC, 12N14P (p = 7 pole pairs), R ≈ 5–15 Ω, L ≈ 1–3 mH |
| Position sensor | 14-bit magnetic encoder (e.g., AS5048/MT6701) per axis |
| Inverter | 3-phase, center-aligned PWM 20 kHz, inline or low-side shunts |
| IMUs | 2× ICM-42688-P on the camera plate, SPI @ 24 MHz, gyro/accel ODR = 8 kHz |
| MCU | Cortex-M4F/M7 (STM32G4/H7), single-precision FPU |

**Loop-rate hierarchy.** Each loop has a bandwidth roughly 4–10× below the loop inside it.

```
 ┌──────────── 20 kHz PWM ISR ─────────────┐
 │ Current loop (FOC), ωc ≈ 2π·1.5 kHz     │
 │ + cogging FF evaluation                 │
 └──────────────▲──────────────────────────┘
                │ iq_ref
 ┌──────────── 8 kHz IMU data-ready ISR ───┐
 │ Dual IMU fusion → notch/LPF → gyro rate │
 │ Velocity (rate) loop, ωv ≈ 2π·150 Hz    │
 └──────────────▲──────────────────────────┘
                │ ω_ref
 ┌──────────── 1 kHz task ─────────────────┐
 │ Mahony AHRS (attitude)                  │
 │ Angle loop, ωθ ≈ 2π·25 Hz               │
 │ Dynamic-notch frequency tracker         │
 └─────────────────────────────────────────┘
```

**Rate-loop feedback source.** The velocity loop is closed on the **inertial gyro rate projected onto the motor axis**, not on encoder velocity. That is what makes a gimbal stabilize the camera against base motion. The encoder is used only for commutation, cogging-map indexing, and the joint-limit/startup estimator.
