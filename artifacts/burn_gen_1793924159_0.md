# 3-Axis Gimbal: FOC Motor Control and Dual-IMU Sensor Fusion (Job #48)

> **Assumptions.** I don't have the Job #48 spec sheet, so this design uses typical gimbal values. Every value marked ⚙ is a parameter you should replace with your measured or spec values.
> - **Motors:** GBM2804-class, 12N14P, so pole pairs p = 7.
> - **Encoder:** 14-bit magnetic (AS5048A or MT6701).
> - **MCU:** STM32G4 or H7 class with FPU.
> - **IMUs:** two ICM-42688-P on SPI, mounted on the camera plate.

---

## 1. Timing Architecture

| Loop | Rate | Ts | Target bandwidth |
|---|---|---|---|
| PWM / current (FOC) | 20 kHz ⚙ | 50 µs | ω_c ≈ 2π·1500 rad/s |
| IMU sampling (both, ODR) | 8 kHz | 125 µs | n/a |
| Velocity loop | 4 kHz | 250 µs | ω_v ≈ 2π·150 rad/s |
| Angle / stabilization loop | 1 kHz | 1 ms | ω_θ ≈ 2π·20 rad/s |

**Bandwidth separation rule:** each outer loop should be at least 5–10× slower than the loop inside it. This lets you treat the inner loop as unity gain when designing the outer loop.

## 2. Field-Oriented Control (Inner Current Loop)

### 2.1 Electrical angle

$$\theta_e = p\,(\theta_m - \theta_{\text{offset}}) \bmod 2\pi$$

The offset θ_offset is found at startup by applying a d-axis voltage and letting the rotor settle.

### 2.2 Clarke transform (amplitude-invariant, with i_a + i_b + i_c = 0)

$$i_\alpha = i_a,\qquad i_\beta = \frac{1}{\sqrt3}\,(i_a + 2 i_b)$$

### 2.3 Park transform

$$\begin{bmatrix} i_d\\ i_q\end{bmatrix} = \begin{bmatrix} \cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix} i_\alpha\\ i_\beta\end{bmatrix}$$

### 2.4 Plant model (surface PMSM, L_d = L_q = L)

$$v_d = R i_d + L\dot i_d - \omega_e L i_q$$

$$v_q = R i_q + L\dot i_q + \omega_e L i_d + \omega_e \lambda_m$$

Electromagnetic torque:

$$\tau_e = \tfrac{3}{2}\,p\,\lambda_m\, i_q = K_t\, i_q$$

### 2.5 Current PI controller with decoupling

**Gain selection by pole-zero cancellation.** Choosing the PI zero to cancel the R/L pole makes the closed loop first-order with bandwidth ω_c:

$$K_p^{i} = \omega_c L,\qquad K_i^{i} = \omega_c R$$

**Control law** (ff = decoupling and back-EMF feedforward):

$$v_d^* = \text{PI}_d(i_d^* - i_d) - \omega_e L\, i_q$$

$$v_q^* = \text{PI}_q(i_q^* - i_q) + \omega_e L\, i_d + \omega_e\lambda_m$$

With i_d* = 0 (no field weakening is needed for a gimbal), the closed-loop response is:

$$\frac{I_q(s)}{I_q^*(s)} = \frac{\omega_c}{s+\omega_c}$$

**Discrete form with back-calculation anti-windup:**

$$u_k = K_p e_k + I_k$$

$$I_{k+1} = I_k + K_i T_s e_k + K_{aw}\,(\text{sat}(u_k) - u_k)$$

A good default is K_aw = 1/K_p.

**Voltage vector limit.** Limit the combined command to the inscribed circle of the SVPWM hexagon:

$$\|v_{dq}\| \le \frac{V_{bus}}{\sqrt3}$$

When saturated, give priority to v_d and use the remaining headroom for v_q.

### 2.6 Inverse Park transform

$$v_\alpha = v_d\cos\theta_e - v_q\sin\theta_e,\qquad v_\beta = v_d\sin\theta_e + v_q\cos\theta_e$$

### 2.7 SVPWM (min-max zero-sequence injection)

1. Compute the phase voltages:
$$v_a = v_\alpha,\quad v_b = -\tfrac12 v_\alpha + \tfrac{\sqrt3}{2}v_\beta,\quad v_c = -\tfrac12 v_\alpha - \tfrac{\sqrt3}{2}v_\beta$$
2. Compute the zero-sequence offset:
$$v_0 = -\tfrac12\left(\max(v_{abc}) + \min(v_{abc})\right)$$
3. Compute the duty cycles:
$$d_x = \tfrac12 + \frac{v_x + v_0}{V_{bus}}$$

This is mathematically equivalent to sector-based SVPWM and is cheaper to compute.

**Latency compensation.** The voltage computed now is applied about 1.5 Ts later. Advance the angle used in the inverse Park transform:

$$\theta_e^{\text{inv}} = \theta_e + 1.5\,\omega_e T_s$$

## 3. Encoder Velocity Estimation (PLL Tracker)

Differentiating raw encoder angle is too noisy. Use a second-order phase-locked loop instead:

$$e_k = \text{wrap}_{\pi}(\theta_{\text{meas},k} - \hat\theta_k)$$

$$\hat\omega_{k+1} = \hat\omega_k + K_i^{pll} T_s e_k$$

$$\hat\theta_{k+1} = \hat\theta_k + T_s(\hat\omega_k + K_p^{pll} e_k)$$

The gains come from the desired natural frequency and damping:

$$K_p^{pll} = 2\zeta\omega_n,\qquad K_i^{pll} = \omega_n^2$$

Typical values: ζ = 1, ω_n ≈ 2π·400 rad/s.

## 4. Cascaded Angle → Velocity Control

For a gimbal, the angle and velocity references should be **inertial (camera) quantities from the IMUs**, not the motor encoders. Per axis j:

### 4.1 Angle loop (1 kHz): P controller plus feedforward

$$\omega_j^* = K_p^{\theta}\,\text{wrap}_\pi(\theta_j^* - \hat\theta_j) + \dot\theta_j^{*}$$

- θ̂_j is the camera attitude projected onto axis j (from the fused quaternion, Section 7).
- θ̇_j* is the user pan or follow rate feedforward.
- A pure P controller is sufficient because the velocity loop already contains an integrator, so the overall loop is type-1. Add a small K_i^θ only if you see steady-state disturbances such as cable drag.
- Design guideline: set K_p
