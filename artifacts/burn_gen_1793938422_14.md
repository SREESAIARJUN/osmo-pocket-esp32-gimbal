I don't have the Job #59 hardware spec, so the design is parameterized and uses the defaults below. Replace them with your values. The structure is the same for any PMSM/BLDC gimbal motor with an absolute magnetic encoder.

## 1. Control Architecture

```
            ┌──────────── 1 kHz ────────────┐ ┌──────── 4 kHz ────────┐ ┌──────── 20 kHz ────────┐
q_ref ──►(attitude err)──► K_θ ──► ω_d,cam ─► J⁻¹ ─► θ̇_d ─►(+)─► Velocity PI ─►(+)─► i_q* ─► Current PI ─► SVPWM
             ▲                                           ▲ −       ▲   i_q,cog(θ_m) ▲            ▲
             │                                    θ̇_meas = J⁻¹ω_gyro   (anti-cogging)  │       Clarke/Park
   Mahony AHRS ◄── dual-IMU fusion ◄── AAF ─ notch ─ LPF ◄── 2×ICM-42688-P             encoder θ_m → θ_e
```

The key gimbal-specific choices are:

1. **Attitude and rate feedback come from the camera IMU, not the encoders.** This rejects base motion directly.
2. **Encoders are used for commutation (θₑ), the gimbal Jacobian, and cogging-table indexing.**
3. **Cogging compensation is injected as current feedforward** after the velocity controller. The velocity PI therefore only handles residual disturbances.

## 2. Field-Oriented Control (Inner Current Loop, 20 kHz)

### 2.1 Electrical Angle
$$\theta_e = p\,(\theta_m - \theta_{\text{off}}) \bmod 2\pi$$

The offset θ_off comes from an alignment procedure: inject $i_d = I_{\text{align}}$ at θₑ = 0, wait for the rotor to settle, then record θ_m.

### 2.2 Clarke Transform
Amplitude-invariant, assuming balanced currents ($i_a + i_b + i_c = 0$):
$$i_\alpha = i_a,\qquad i_\beta = \frac{1}{\sqrt3}(i_a + 2 i_b)$$

### 2.3 Park Transform
$$\begin{bmatrix} i_d\\ i_q\end{bmatrix} = \begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix} i_\alpha\\ i_\beta\end{bmatrix}$$
