# 3-Axis Gimbal FOC Control & Dual-IMU Fusion: Design Specification and C++ Reference (Job #48)

I don't have the Job #48 hardware specification, so this design uses the assumptions in §0. Every assumed value is a named constant in the code. Replace them with your measured motor, encoder and frame data before tuning.

## 0. Assumptions and Architecture

| Item | Assumed value |
|---|---|
| Motors | Gimbal BLDC, 12N14P (7 pole pairs), R ≈ 8 Ω, L ≈ 3 mH, Kt ≈ 0.08 N·m/A |
| Encoder | 14-bit absolute magnetic (AS5048A / MT6701 class) |
| Current sense | 2-shunt inline, center-aligned PWM |
| MCU | Cortex-M4F/M7 with single-precision FPU |
| IMUs | 2× ICM-42688-P on separate SPI buses, mounted on the camera plate symmetric about the plate centroid (r₂ = −r₁) |
| Mechanical order | Base → Yaw → Roll → Pitch → Camera |

**Loop rates (all run synchronously from the PWM timer):**

```
PWM / current loop (FOC)    20 kHz  (Ts_i = 50 µs)   ISR: ADC-complete
Velocity loop + PLL          4 kHz  (Ts_v = 250 µs)  every 5th current ISR
IMU sample (ODR)             8 kHz  read via DRDY, decimated 2:1 → 4 kHz
Attitude / angle loop        1 kHz  (Ts_θ = 1 ms)
Cogging LMS adaptation       4 kHz  (gated)
```

**Signal flow per axis:**

```
 q_ref ──►[Attitude P + rate FF]──ω_cam*──►[J⁻¹(q)]──q̇*──►[Velocity PI-D]──i_q*──►(+)──►[FOC PI d/q]──►SVPWM
                 ▲                               ▲                  ▲                  ▲
           IMU quaternion               gyro (cam frame)        PLL ω̂ (joint)    i_ff,cog(θ_m)
```
