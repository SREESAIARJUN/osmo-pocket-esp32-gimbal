# Job #53: 3-Axis Gimbal FOC Control Loop and Dual-IMU Sensor Fusion

I have no hardware details for Job #53 beyond the two ICM-42688-P IMUs, so the design rests on the assumptions in §0. Every parameter that depends on them is a named constant in the code. Re-derive the gains (§2–§3) once you measure R, L, Kt, J and the cogging spectrum on the real motors.

---

## 0. Assumptions and Architecture

| Item | Assumed value |
|---|---|
| Motors | Gimbal BLDC, 12N14P, so p = 7 pole pairs, Ns = 12 slots |
| Phase params (line-neutral) | R = 5.0 Ω, L = 1.2 mH, Kt = 0.08 N·m/A |
| Encoder | 14-bit absolute magnetic encoder (AS5048A / MT6701 class), SPI |
| Inverter | 3-phase, center-aligned PWM at 20 kHz, 2 low-side shunts, Vbus = 16.8 V (4S) |
| IMU A/B | Two ICM-42688-P on the camera payload, rigidly mounted, same orientation, separate SPI buses |
| Gimbal order | Base → yaw (z) → roll (x) → pitch (y) → camera |
| MCU | Cortex-M7 / M4F with FPU (STM32G4/H7 class) |

### Loop rates and bandwidth separation

Each loop's bandwidth is kept at least 4–5× below the loop inside it.

```
 20 kHz  ISR (ADC-triggered)  : current PI (id, iq), SVPWM, encoder angle, anti-cogging FF
  8 kHz  IMU data-ready ISR   : read A & B gyro/accel, notch + LPF, dual-IMU fusion
  4 kHz  velocity loop        : PI on inertial joint-rate error  -> iq*
  1 kHz  attitude/angle loop  : Mahony AHRS, quaternion error -> rate command
```

Bandwidth targets:

| Loop | Target bandwidth |
|---|---|
| Current | ω_ci ≈ 2π·1500 rad/s |
| Velocity | ω_cv ≈ 2π·60 rad/s |
| Angle | ω_cθ ≈ 2π·12 rad/s |

## 1. Field-Oriented Control (Current Loop, 20 kHz)

### 1.1 Electrical angle with latency compensation

The encoder count is converted to a mechanical angle:

  θ_m = 2π · (N_enc − N_offset) / 2¹⁴

The electrical angle is θ_e = p·θ_m (mod 2π).
