# 3-Axis Gimbal: FOC Motor Control and Dual-IMU Sensor Fusion Design

I don't have the Job #39 specification, so the design below is built on the assumptions in §0. Every hardware-dependent constant is isolated in a config struct, so you can substitute your real values without changing the math.

---

## 0. Baseline Assumptions

| Item | Assumed value |
|---|---|
| MCU | STM32G4 / H7 class (FPU, ≥170 MHz), center-aligned PWM |
| Motors | Gimbal BLDC, 12N14P (7 pole pairs), R ≈ 5–15 Ω, L ≈ 2–5 mH |
| Encoder | 14-bit absolute magnetic (AS5048A / MT6701) on each joint |
| Current sensing | 2-shunt low-side (inline also works). A voltage-mode fallback is provided. |
| IMUs | 2 × ICM-42688-P on the camera plate (SPI, 24 MHz, ODR 8 kHz). IMU B is rotated 180° about z. |
| Kinematic order | Base → Yaw (z) → Roll (x) → Pitch (y) → Camera |

### Loop rates

| Loop | Rate | Ts |
|---|---|---|
| PWM / current (FOC) | 20 kHz | 50 µs |
| IMU sampling + vibration filters | 8 kHz | 125 µs |
| Velocity (rate) loop + cogging FF | 4 kHz | 250 µs |
| Attitude fusion + angle loop | 1 kHz | 1 ms |

**Bandwidth separation rule:** each loop should be at least 4–5× slower than the loop inside it:

ω_c,i ≈ 2π·1500 rad/s,  ω_c,ω ≈ 2π·120 rad/s,  ω_c,θ ≈ 2π·20 rad/s

## 1. FOC Inner Current Loop

### 1.1 Transforms (amplitude-invariant)

**Clarke:**

i_α = i_a,  i_β = (i_a + 2i_b)/√3  (assumes i_a + i_b + i_c = 0)

**Park:**

i_d = i_α cos θ_e + i_β sin θ_e
i_q = −i_α sin θ_e + i_β cos θ_e

**Electrical angle:**

θ_e = p(θ_m − θ_off)
