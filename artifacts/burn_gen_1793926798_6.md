# Gimbal Job #41: FOC Control Loop and Dual-IMU Sensor Fusion

**Scope:** cascaded FOC (current, velocity, angle), anti-cogging feedforward, dual ICM-42688-P vibration rejection, 3-axis kinematics, and a C++17 reference implementation.

> **Assumptions to confirm.** I don't have the Job #41 spec sheet, so the design is parameterized. The defaults are:
> - Motors: 12N14P gimbal BLDC (7 pole pairs).
> - Encoder: 14-bit magnetic (AS5048A or MT6701).
> - MCU: STM32G4-class at 170 MHz with FPU.
> - PWM and current loop: 20 kHz.
>
> All of these are constructor parameters. Replace the motor constants with measured values.

---

## 1. Timing Architecture

| Loop | Rate | Bandwidth target | Source |
|---|---|---|---|
| Current (d/q PI) | 20 kHz | ω_c ≈ 2π·1.5 kHz | Shunt ADC, synced to PWM center |
| IMU sample + filters | 8 kHz | n/a | 2× ICM-42688-P, SPI DMA, ODR = 8 kHz |
| Velocity (PI) | 4 kHz | ω_v ≈ 2π·80 Hz | Fused gyro mapped to joint axis |
| Angle / attitude (P + FF) | 1 kHz | ω_p ≈ 2π·15 Hz | Quaternion attitude estimate |
| Cogging LMS adaptation | 4 kHz (gated) | Slow (τ ≈ seconds) | Velocity PI output |

Each loop's bandwidth is 4–10× below the loop inside it. This separation lets each outer loop treat the inner loop as unity gain plus a small delay.
