# Job #51: 3-Axis Gimbal FOC Control Loop and Dual-IMU Sensor Fusion

This document covers the current-loop FOC, the cascaded angle and velocity control, anti-cogging feedforward, the dual ICM-42688-P vibration-rejection chain, and a complete C++17 implementation.

Because Job #51's hardware details were not supplied, this design is built on stated assumptions, and every value marked *(param)* must be replaced with measured data before hardware testing.

## 0. Design Assumptions and Timing Architecture

| Item | Value *(param)* |
|---|---|
| MCU | STM32G474 @ 170 MHz, FPU, CORDIC, 3× ADC |
| Motors | Gimbal BLDC, 12N14P (p = 7 pole pairs), R ≈ 8 Ω, L ≈ 2.5 mH, Kt ≈ 0.09 N·m/A |
| Encoder | AS5048A / MT6701, 14-bit absolute, SPI, read once per velocity tick |
| IMUs | 2× ICM-42688-P on the camera payload, SPI @ 24 MHz, gyro/accel ODR 8 kHz |
| Kinematic order | Yaw (base) → Roll → Pitch (camera) |

The loop rates are chosen so that each layer is an integer division of the PWM clock:

```
PWM / ADC / current loop : 24 kHz    (Ts_i = 41.67 µs)
IMU sample + filtering   :  8 kHz    (DMA from ICM-42688-P, data-ready aligned)
Velocity loop + encoder  :  8 kHz    (÷3, aligned with IMU)
Angle / attitude loop    :  1 kHz    (÷24)
Cogging learning (LMS)   :  8 kHz    (gated)
```

The design bandwidths follow the usual ≥5× separation rule between cascaded layers:

| Layer | Bandwidth |
|---|---|
| Current | f_c = 1.5 kHz |
| Velocity | f_v = 120 Hz |
| Angle | f_θ = 20 Hz |
