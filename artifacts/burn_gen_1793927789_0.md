# FOC Motor Control and Dual-IMU Sensor Fusion for a 3-Axis Gimbal

I don't have the original spec for Job #51, so the design below states its assumptions explicitly (§0). Every gain is derived from plant parameters, so you can substitute your real numbers without changing the structure.

## 0. Assumptions and Loop Architecture

| Item | Assumed value |
|---|---|
| Motor | 12N14P gimbal BLDC (e.g. GBM2804-class): pole pairs `p = 7`, `R = 10 Ω`, `L = 3 mH`, `Kt ≈ 0.06 N·m/A` |
| Commutation sensor | 14-bit absolute magnetic encoder (AS5048A / MT6701 class) |
| Current sense | 2-phase inline shunts. If you have no current sensing, use voltage mode (see §1.6). |
| IMUs | 2 × ICM-42688-P, both on the camera plate at opposite corners, SPI at 24 MHz, ODR 8 kHz |
| MCU | Cortex-M4F/M7 with single-precision FPU |

### Rate partitioning

The bandwidth separation between nested loops is at least 5–10×.

```
PWM / FOC current loop   20 kHz   (ωc_i ≈ 2π·1.5 kHz)
IMU sample + filtering    8 kHz
Rate (velocity) loop      4 kHz   (ωc_v ≈ 2π·120 Hz)
Attitude/angle loop       1 kHz   (ωc_θ ≈ 2π·25 Hz)
Attitude estimator        1 kHz   (Mahony)
```

### Signal flow per axis

```
 θ_ref ─►(+)─► P/PI_θ ─► ω_ref ─►(+)─► PI_ω ─► i_q,fb ─►(+)─► PI_iq ─► v_q ─► invPark ─► SVPWM ─► motor
          ▲(-)                ▲(-)                       ▲  ▲(-)
     θ̂ (Mahony,          ω_axis (dual-IMU,        i_q,cog (anti-cogging)
     projected)           notch + LPF)            + J·ω̇_ref (inertial FF)
                                          encoder θ_m ─► Park / commutation, PLL ω_enc
```

The inner rate loop runs on inertial gyro rate projected onto the motor axis, not on encoder rate. Using the gyro is what rejects base motion. The encoder is used for:

- commutation,
- cogging-phase lookup,
- joint-angle kinematics,
- low-frequency blending.
