# FOC Control Loop and Dual-IMU Sensor Fusion for the 3-Axis Gimbal (Job #54)

## 0. Assumptions

No hardware spec was provided for Job #54, so the design uses the assumptions below. Every one of them is a parameter in the code.

| Item | Assumed value |
|---|---|
| Motor | Gimbal BLDC, 12N14P (p = 7 pole pairs), R ≈ 5 Ω, L ≈ 2 mH, Kt ≈ 0.08 N·m/A |
| Commutation sensor | 14-bit absolute magnetic encoder (AS5048A / MT6701 class) on each joint |
| Inverter | 3-phase, center-aligned PWM, 20 kHz, synchronous low-side shunt sampling |
| IMUs | 2× ICM-42688-P on the camera platform (rigid body), SPI, 8 kHz ODR |
| MCU | Cortex-M4F/M7 (STM32G4/H7 class), single-precision FPU |
| Loop rates | Current 20 kHz (ISR), velocity 4 kHz, angle 1 kHz, attitude fusion 4 kHz |

Gimbals are a special case for the loop hierarchy:

- The **encoder** is used only for commutation and as an independent rate reference.
- The **stabilization loops** close on the IMU, because the requirement is camera inertial attitude, not joint angle.

## 1. System Architecture

```
            ┌────────── 1 kHz ──────────┐ ┌──── 4 kHz ────┐ ┌─────── 20 kHz ───────┐
 q_ref ──►  Attitude error → joint err ─► Angle P ─► ω_ref ─► Velocity PI ─► i_q* ─┐
            ▲ (inverse Jacobian)                   ▲                 + i_cog_ff ◄─┤ Anti-cogging(θ_m, ω)
            │                                      │                              ▼
     q̂ (Mahony) ◄── fused ω, a ◄── Dual-IMU ◄── ICM-42688 ×2      Current PI (d,q) + decoupling
                                    filters                         → inv. Park → SVPWM → inverter
                      encoder θ_m ─► θ_e, ω_enc ───────────────────────────────┘
```

## 2. Field-Oriented Current Loop (20 kHz)

### 2.1 Transforms (amplitude-invariant)

**Clarke transform** (assuming i_a + i_b + i_c = 0):

$$
i_\alpha = i_a,\qquad i_\beta = \frac{i_a + 2 i_b}{\sqrt3}
$$
