# 3-Axis Gimbal Control Design: FOC, Cascaded PID, Anti-Cogging, and Dual ICM-42688-P Fusion

I don't have the specifications for "Job #17", so this design states its hardware assumptions explicitly. Every assumption is a named constant in the code, so you can change any of them in one place.

---

## 0. Assumptions and Loop Architecture

| Item | Value |
|---|---|
| MCU | STM32G4 / H7 class (Cortex-M4F/M7, single-precision FPU) |
| Motors | 3 × gimbal BLDC, 12N14P (pole pairs p = 7), R ≈ 5 Ω, L ≈ 2 mH, Kt ≈ 0.06 N·m/A |
| Commutation encoder | 14-bit magnetic (MT6701 / AS5047), one per axis |
| Current sensing | 2-phase inline shunts |
| IMUs | 2 × ICM-42688-P on the camera plate, separate SPI chip-selects |
| PWM / current loop | 20 kHz, center-aligned, ISR synced to the PWM midpoint |
| IMU ODR | 8 kHz, with filters run at 8 kHz |
| Velocity loop | 4 kHz (decimated by 2) |
| Angle loop | 1 kHz |

```
 IMU1 ─┐  AAF(on-chip) → frame rot → lever-arm fusion → dyn. notch ×2 → PT1 ─┐
 IMU2 ─┘                                                                     │
                                         Mahony AHRS (1–8 kHz) ◄─────────────┤
                                                │ q_cam                      │ ω_cam (filtered)
 setpoint ─► [Angle P + FF] ─ω*─► [Velocity PI] ─iq*─► (+ iq_cog_ff) ─► [Current PI dq] ─► SVPWM
             (1 kHz)               (4 kHz)                ▲               (20 kHz)
                                                 Anti-cogging LUT/LMS (θ_m from encoder)
```

The key design choice: **the velocity loop uses gyro rate as feedback, not differentiated encoder angle.** Gyro rate is the inertial quantity you actually want stabilized. The encoder serves three purposes only:

- commutation,
- cogging compensation, and
- joint-limit and initialization logic.
