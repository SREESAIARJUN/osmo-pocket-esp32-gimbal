# 3-Axis Gimbal: FOC Control Loop and Dual-IMU Sensor Fusion Design

I don't have the specification for Job #18, so this design rests on the assumptions in §0. Every motor- and IMU-specific number is a named constant in the code, so substitute your values where they differ.

---

## 0. Assumptions and Loop Architecture

| Item | Assumed value |
|---|---|
| MCU | STM32G474 class, 170 MHz, single-precision FPU |
| Motor | Gimbal BLDC, 12N14P (pole pairs p = 7), R ≈ 5.6 Ω, L ≈ 2.1 mH (phase), K_t ≈ 0.08 N·m/A |
| Rotor sensor | 14-bit absolute magnetic encoder (AS5048A / MT6701 class), one per axis |
| Current sense | Inline or low-side shunts, sampled center-aligned with the PWM |
| IMUs | 2 × ICM-42688-P on the camera plate, SPI at 24 MHz, ODR 8 kHz, sharing a 32 kHz CLKIN |
| Gimbal order | Yaw (base) → Roll → Pitch (camera) |

**Loop timing**

```
 20 kHz  ── Current loop (FOC: Clarke/Park, PI d/q, SVPWM)        [ADC ISR]
  8 kHz  ── IMU read ×2 → dual-IMU fusion → vibration filters    [IMU DRDY ISR]
  4 kHz  ── Velocity loop (gyro rate feedback) + anti-cogging FF  [decimated from 20 kHz]
  1 kHz  ── Attitude estimator (Mahony) + angle loop              [timer task]
```

**Cascade, per axis i**

```
θ_ref ─►(+)─► C_θ (P + rate FF) ─► ω_ref ─►(+)─► C_ω (PI + AW) ─►(+)─► i_q,ref ─► FOC current PI ─► motor
        ▲−                                  ▲−                    ▲ +
     θ̂ (Mahony / IMU)                  ω̂ (filtered fused gyro)   i_q,cog (anti-cogging FF)
```

Two sensors play different roles.
