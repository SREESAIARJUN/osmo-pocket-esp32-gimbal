## 0. Architecture Clarifications

Two premises in the brief need to be settled before the math.

**1. The H743 does not commutate the motors.** ArduPilot is a flight-control stack. It does not run 6-step or FOC commutation at 48 kHz. A 4-in-1 ESC carries its own MCU(s), normally one per motor (AT32F421, STM32G071, or GD32 running AM32 or BLHeli_32). The 48 kHz switching analysis applies to those ESC MCUs. The H743 generates DShot600 frames and decodes the bi-directional eRPM telemetry. The two-tier architecture below is assumed throughout.

```
 STM32H743 (ArduPilot) ──DShot600 bidir x4──► 4x ESC MCU (AM32/BLHeli_32, 48 kHz PWM)
                                               └─► 4x 3-phase gate driver ─► 24x MOSFET
```

**2. 80 A per motor on a nano (20×20 mm mount) board is a burst-only rating.** The math below shows this rating is time-limited to seconds. It is set by board heat capacity, not by the MOSFET datasheet. Treat 80 A as a ≤1–2 s per-motor rating. A simultaneous 4×80 A event is thermally and electrically unrealistic on this form factor (Section 4.4).

**Parameter assumptions.** All parameters are representative. Replace each with the datasheet value for the chosen BOM.

## 1. Conduction Loss Model

### 1.1 Current paths in synchronous 6-step

In any commutation sector:
- Phase A switches with duty D. The high side (HS) conducts during D·T. The complementary low side (LS) conducts during (1−D)·T.
- Phase B's LS is held on continuously.
- Phase C floats (BEMF sensing).

The motor current therefore always flows through exactly **two FET channels** in series:

$$
P_{cond,motor} = I_{rms}^2 \cdot 2\,R_{ds}(T_j)
