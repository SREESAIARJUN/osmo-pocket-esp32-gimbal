## 0. Architecture Assumptions and Critical Feasibility Finding

**Topology.** The STM32H743 is the flight controller (FC) running ArduPilot. It does **not** commutate the motors directly. Each of the four ESC channels has its own small MCU running AM32 or BLHeli_32-class firmware, which accepts bi-directional DShot600. A 4-in-1 ESC using the H743 as the commutation controller would be non-standard and would need custom firmware, so that is not the baseline here.

| Parameter | Value (assumed) |
|---|---|
| Battery | 6S LiPo, V_bus = 25.2 V max, 22.2 V nominal |
| PWM frequency (ESC) | f_sw = 48 kHz, center-aligned, synchronous rectification ("complementary PWM") |
| Commutation | 6-step trapezoidal (AM32 default). The FOC variant is noted where it differs. |
| Burst current | **80 A per channel** (interpreted literally), 320 A total |
| MOSFET (reference device) | 40 V N-ch, PQFN 3.3×3.3, R_DS(on) = 1.5 mΩ @ 25 °C, Q_g = 35 nC, Q_gd = 8 nC, Q_rr = 40 nC, Q_oss = 30 nC, V_SD = 0.8 V |
| Board | 30.5×30.5 mm mount, ~36×36 mm outline, 8-layer, 2 oz copper on power layers |

> ⚠️ **Feasibility finding (read first).** The derivation below shows that 80 A per channel on a nano-format board is **thermally a short-burst rating only (≈1–2 s)**. Sustained capability is ~25–30 A per channel. Physics sets this limit, not component choice.
>
> Additional system-level problems at 320 A total:
> - It implies roughly 7–8 kW from the pack.
> - XT30/XT60 connectors and nano-class power leads cannot carry it.
> - Single-shunt current sensing would itself dissipate ~10 W.
>
> If "80 A burst" was meant as **total** board current (20 A per channel), every equation below still applies. Section 2.6 tabulates both cases. **Confirm which spec is intended before layout.**

All device values are representative. Re-run the models with the selected part's datasheet values: R_DS(on)(T), Q_g, Q_rr, and the transient Z_th curve.
