# STM32H743 FC + 4-in-1 ESC (Job #31): Loss Model, DShot Allocation, and Netlist

## 0. Architecture Corrections

Three points change the design before any math applies:

1. **The H743 does not commutate the motors.** A 4-in-1 ESC needs its own commutation MCUs, either one per channel (e.g., STM32G071 or AT32F421 running AM32) or a dual-motor controller. The H743 runs ArduPilot and talks to the ESC MCUs over bi-directional DShot600. Section 3 is written on that basis.
2. **"80A burst" on a nano (20×20 mm) board is thermally marginal.** The model below shows it is survivable only for seconds, not tens of seconds. Treat 80A as a short transient rating with firmware current limiting, not as a continuous capability.
3. **All component parameters below are representative assumptions**, typical of 40V, 0.7 mΩ-class 3.3×3.3 mm MOSFETs. Replace them with your chosen part's datasheet values before sign-off.

## 2. Thermal and Loss Model

### 2.1 Conduction Loss

In any commutation sector, current flows through exactly two FETs in series:
- During PWM-on: high-side FET of phase A, the motor, and low-side FET of phase B.
- During PWM-off: low-side FET of phase A (synchronous rectification), the motor, and low-side FET of phase B.

So two R_DS(on) are always in the path, independent of duty cycle:

$$P_{cond} = 2\,I^2\,R_{DS(on)}(T_j), \qquad R_{DS(on)}(T_j) = R_0\left[1+\alpha(T_j-25)\right] \approx k_T R_0$$

$$P_{cond} = 2 \times 80^2 \times (1.5 \times 0.7\times10^{-3}) = \mathbf{13.44\ W}$$

Copper loss in the traces, planes, and solder joints:

$$P_{cu} = I^2 R_{cu} = 6400 \times 0.5\times10^{-3} = \mathbf{3.20\ W}$$

Note that the phase current at partial throttle is I_phase ≈ I_bat / D. "80A battery current" at 50% duty therefore means roughly 160A phase current. Specify which current the burst rating refers to; this model uses 80A **phase** current.

### 2.2 Switching Loss (Hard-Switched High-Side, 48 kHz)

**V–I overlap:**

$$P_{sw} = \tfrac{1}{2} V_{bus} I (t_r+t_f) f_{sw} = 0.5 \times 25.2 \times 80 \times 40\text{ns} \times 48\text{k} = \mathbf{1.94\ W}$$

**Reverse recovery** (low-side body diode, dissipated mostly in the high-side FET):

$$P_{rr} = Q_{rr} V_{bus} f_{sw} = 50\text{n} \times 25.2 \times 48\text{k} = \mathbf{0.06\ W}$$

**Dead-time diode conduction** (two dead-time intervals per period):

$$P_{dt} = V_f I \,(2 t_{dt}) f_{sw} = 0.8 \times 80 \times 200\text{n} \times 48\text{k} = \mathbf{0.61\ W}$$

**C_oss loss:**

$$P_{oss} = \tfrac{1}{2} C_{oss} V_{bus}^2 f_{sw} = 0.5 \times 2\text{n} \times 635 \times 48\text{k} = \mathbf{0.03\ W}$$

**Gate drive** (two switching FETs per sector; this loss is dissipated in the driver, not the FET):

$$P_g = 2\,Q_g V_{gs} f_{sw} = 2 \times 60\text{n} \times 10 \times 48\text{k} = \mathbf{0.06\ W}$$

### 2.3 Totals at 80A Burst

| Loss | Per channel (W) | 4 channels (W) |
|---|---|---|
| Conduction (FETs) | 13.44 | 53.8 |
| Copper | 3.20 | 12.8 |
| Switching overlap | 1.94 | 7.8 |
| Dead-time diode | 0.61 | 2.4 |
| Q_rr + C_oss + gate | 0.15 | 0.6 |
| **Total** | **≈19.3** | **≈77.4** |

Two design conclusions follow:
- **Conduction dominates.** Reducing f_sw from 48 kHz to 24 kHz saves only about 1.3 W per channel.
- **Doubling FETs in parallel per switch roughly halves the 13.4 W conduction term.** This is the biggest available lever, if the board area allows it.

### 2.4 Hottest Device: Junction Temperature

The high-side FET in the conducting phase carries roughly half the conduction loss plus nearly all the switching loss:

$$P_{HS} \approx 6.72 + 1.94 + 0.06 + 0.3 \approx 9.0\text{ W}$$

Junction-to-case rise (steady state):

$$\Delta T_{jc} = 9.0 \times 1.0 = 9\text{ K}$$

The real limit is the **board**, not the die.

### 2.5 Board-Level Transient (Burst Duration Limit)

Model the ESC as a lumped thermal mass with prop-wash convection:

$$C_{th}\frac{dT}{dt} = P - \frac{T-T_a}{R_{\theta,ba}} \quad\Rightarrow\quad T(t) = T_a + P R_{\theta,ba}\left(1-e^{-t/\tau}\right),\ \ \tau = R_{\theta,ba} C_{th}$$

Nano estimates:
- Board, FETs, and copper mass ≈ 8 g, with c ≈ 0.9 J/g·K, so C_th ≈ 7.2 J/K.
- R_θ,ba ≈ 4 K/W with prop airflow (≈ 15 K/W in still air).
- τ ≈ 29 s.

Initial heating slope at 77 W is 77 / 7.2 ≈ **10.7 K/s**.

Allowable board rise from 40°C ambient to a 110°C board limit (keeping T_j ≤ ~125°C):

$$t_{max} = -\tau \ln\left(1 - \frac{\Delta T}{P R_\theta}\right) = -29\ln\left(1-\frac{70}{308}\right) \approx \mathbf{7.5\ s}$$

The steady-state rise at 77 W would be 308 K, so 80A is non-sustainable. The sustainable all-channel continuous current from the same model (ΔT = 70 K, so P ≈ 17.5 W total, ≈ 4.4 W per channel) is approximately:

$$I_{cont} \approx 80\sqrt{4.4/19.3} \approx \mathbf{38\ A\ per\ channel}$$

**Required mitigations:**
- Set the ESC firmware current limit (AM32 `current limit`) to about 40A continuous.
- Enable temperature protection using an NTC on the ESC board.
- In ArduPilot, monitor ESC telemetry temperature (`ESC_TLM`) and current.

## 3. ArduPilot Bi-Directional DShot600 Timer and DMA Allocation

### 3.1 DShot600 Timing

| Item | Value |
|---|---|
| Bit rate | 600 kbit/s, so T_bit = 1.667 µs |
| T0H / T1H | ≈ 0.625 µs / 1.25 µs (37.5% / 75%) |
| Frame | 16 bits = 26.7 µs, plus inter-frame gap |
| Timer clock | H743 @ 400 MHz SYSCLK; APB timer clock 200 MHz. ArduPilot computes the prescaler/ARR automatically |
| Telemetry return | GCR-encoded, 21 bits at 5/4 × 600 = 750 kbit/s, ≈ 30 µs after the frame, on the **same pin** (inverted signalling) |

### 3.2 DMA Requirements

- **Output:** Each timer group uses one burst DMA on **TIMx_UP** to write all channels' CCR registers.
- **Bi-directional input:** Each telemetry capture needs a **TIMx_CHy capture DMA**. ArduPilot reuses streams by switching between output and input phases, but the stream must still be resolvable.
- **H7 DMAMUX:** Any request can map to any of the 16 DMA1/DMA2 streams. The constraint is therefore **stream count**, not fixed mapping. Budget: 4 motors bidir, plus UARTs with DMA, plus SPI (IMU, baro/flash, OSD).
- **Pin restrictions:**
  - Do **not** use complementary (CHxN) outputs; they are not supported for bidir capture.
  - Avoid timers shared with other functions such as the LED strip.
  - Keep all 4 motors on **at most 2 timers** to minimise UP-DMA streams.

### 3.3 Recommended Mapping

| Motor | Pin | Timer/Ch | Notes |
|---|---|---|---|
| M1 | PB0 | TIM3_CH3 | BIDIR |
| M2 | PB1 | TIM3_CH4 | BIDIR |
| M3 | PA0 | TIM5
