# FOC Motor Control and Dual-IMU Sensor Fusion for a 3-Axis Gimbal

I don't have a prior specification for "Job #11", so this design states its assumptions explicitly. The equations are written symbolically, so they hold if your hardware differs. Only the numeric defaults need changing.

## 0. Assumptions and Timing Architecture

| Item | Assumed value |
|---|---|
| Motors | Hollow-shaft gimbal BLDC (GBM2804-class): 12 slots, 14 poles (p = 7 pole pairs), R ≈ 5 Ω, L ≈ 2 mH, Kt ≈ 0.08 N·m/A |
| Rotor encoder | 14-bit absolute magnetic encoder (AS5048A/MT6701), one per axis |
| IMUs | 2× ICM-42688-P on the camera plate, separate SPI buses, data-ready IRQ |
| MCU | Cortex-M4F/M7 with FPU (STM32G474 / H7) |
| Bus | 12–16 V, center-aligned PWM |

**Loop rates.** Each outer loop runs well below the bandwidth of the loop inside it.

| Loop | Rate | Closed-loop bandwidth |
|---|---|---|
| Current (FOC, d/q PI) | 20 kHz | ω_c ≈ 2π·1.5 kHz |
| IMU sampling, filtering, fusion | 8 kHz | n/a |
| Velocity (inertial rate) | 4 kHz | ω_v ≈ 2π·80 Hz |
| Angle (attitude) | 1 kHz | ω_θ ≈ 2π·15 Hz |
| Cogging adaptation and notch retune | 1 kHz | slow |

## 1. FOC Current Loop

### 1.1 Transforms
Electrical angle from the mechanical encoder angle θ_m:
$$\theta_e = p\,(\theta_m - \theta_{off}) \bmod 2\pi$$

Amplitude-invariant Clarke transform, assuming i_a + i_b + i_c = 0:
$$i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}(i_a + 2 i_b)$$
