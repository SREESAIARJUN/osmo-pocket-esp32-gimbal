# Job #49: 3-Axis Gimbal FOC Control and Dual-IMU Sensor Fusion

## 0. Assumptions

You did not include the Job #49 spec, so this design rests on the defaults below. Every one is a `constexpr` or config field in the code, so you can change them in one place.

| Item | Assumption |
|---|---|
| Motors | 3× gimbal BLDC, 12N14P (pole pairs p = 7), R ≈ 5–10 Ω, L ≈ 2–4 mH |
| Position sensor | 14-bit absolute magnetic encoder per joint (AS5048A / MT6701 class) |
| Current sense | 2 or 3 low-side shunts, sampled at PWM center |
| MCU | STM32G4/H7 class, FPU, 170+ MHz |
| Kinematics | Yaw (outer) → Roll → Pitch (inner, camera) |
| IMUs | 2× ICM-42688-P on the camera plate, mounted roughly symmetric about the payload rotation center, each on its own SPI bus |
| Loop rates | Current/FOC 20 kHz · rate (velocity) 4 kHz · attitude 1 kHz · IMU ODR 8 kHz |

## 1. System Architecture

```
            1 kHz                      4 kHz                          20 kHz
q_ref ──► [Attitude P] ─ω_cmd─► [Rate loop: e_ω → J⁻¹(θ) → 3× PI] ─iq_ref─► (+) ─► [FOC PI id/iq] ─► SVPWM
             ▲                        ▲                                       ▲          ▲
             │ q̂                     │ ω̂_cam (filtered)        iq_ff(θm)────┘          │ θe, ia, ib
     [Mahony AHRS] ◄── [Dual-IMU fusion + notch/LPF] ◄── 2× ICM-42688-P      [Encoder PLL → θm, ω_m]
```

- The encoder is used for commutation, the Jacobian, cogging lookup and joint-space modes (follow/lock).
- The camera IMUs close the stabilization loops, so base vibration is rejected inertially.
