# 3-Axis Gimbal: FOC Motor Control, Anti-Cogging, and Dual-IMU Vibration Rejection

I don't have the Job #28 specification, so this design states its assumptions explicitly. Every number below is a parameter. Change it to match your hardware and the equations and code still apply.

---

## 0. Assumptions and Loop Architecture

| Item | Assumed value |
|---|---|
| MCU | STM32G474 (Cortex-M4F, 170 MHz, single-precision FPU) |
| Motors | Gimbal BLDC, 12N14P (pole pairs $p=7$), $R_s\approx 5.6\,\Omega$, $L_s\approx 1.2$ mH, $K_t\approx 0.09$ Nm/A |
| Encoders | 14-bit magnetic encoder per joint (AS5048A / MT6701), SPI |
| IMUs | 2 × ICM-42688-P on the camera plate, SPI, 8 kHz gyro ODR, 1 kHz accel ODR, data-ready interrupt |
| Kinematics | Outer **yaw (z)** → middle **roll (x)** → inner **pitch (y)** → camera |

The control loops run at these rates:

```
 20 kHz  ── Current loop (FOC: Clarke/Park, PI d/q, decoupling, SVPWM)  ← ADC JEOC ISR
  8 kHz  ── IMU read ×2, notch/LPF filtering, dual-IMU fusion           ← IMU DRDY ISR
  4 kHz  ── Rate loop (inertial camera rate, joint-space PI) + anti-cogging FF
  1 kHz  ── Attitude estimation (Mahony on SO(3)) + angle loop (quaternion error)
```

The loops are deliberately split by role:

- **Commutation uses the encoder.** Rotor flux angle has to be known exactly.
- **Stabilization uses the IMU.** The quantity being controlled is the camera's *inertial* attitude.

## 1. FOC Current Loop (Innermost, 20 kHz)

### 1.1 Transforms

Electrical angle (with $\theta_{off}$ found by an alignment routine):

$$\theta_e = p\,(\theta_m - \theta_{off})$$

Clarke transform (amplitude-invariant, 3 shunts, $i_a+i_b+i_c=0$):

$$i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}(i_a + 2 i_b)$$

Park transform:

$$\begin{bmatrix} i_d \\ i_q \end{bmatrix} = \begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix} i_\alpha \\ i_\beta\end{bmatrix}$$

### 1.2 Plant and Decoupling

The PMSM model in the rotor frame ($L_d = L_q = L$ for a surface-mount gimbal motor) is:

$$v_d = R i_d + L\dot i_d - \omega_e L i_q,\qquad v_q = R i_q + L\dot i_q + \omega_e L i_d + \omega_e\lambda_m$$

Feedforward decoupling cancels the cross-coupling and back-EMF terms:

$$v_d = u_d - \hat\omega_e \hat L i_q,\qquad v_q = u_q + \hat\omega_e \hat L i_d + \hat\omega_e \hat\lambda_m$$

What remains on each axis is a first-order plant, $G_i(s) = \frac{1}{Ls+R}$.

### 1.3 PI Design by Pole-Zero Cancellation

Choose the PI controller $C_i(s)=K_p + K_i/s$ with:

$$K_p = L\,\omega_{ci},\qquad K_i = R\,\omega_{ci}$$

The controller zero $K_i/K_p = R/L$ cancels the plant pole, so the closed loop becomes:

$$T_i(s) = \frac{\omega_{ci}}{s+\omega_{ci}}$$

Choose $\omega_{ci} \le 2\pi f_{pwm}/20$. At 20 kHz this gives $\omega_{ci}\approx 2\pi\cdot 1000$ rad/s.

The one-cycle computation delay plus PWM zero-order hold contribute $\approx 1.5\,T_s$ of delay. Phase margin is therefore:

$$PM \approx 90^\circ - \omega_{ci}\cdot1.5T_s\cdot\tfrac{180}{\pi} \approx 79^\circ$$

### 1.4 Discretization and Anti-Windup

Use the forward-Euler integrator with back-calculation anti-windup ($K_{aw} = 1/K_p$ is a robust default):

$$u[k] = K_p e[k] + x[k],\quad \bar u[k] = \mathrm{sat}(u[k])$$
$$x[k+1] = x[k] + K_i T_s e[k] + K_{aw}\,(\bar u[k]-u[k])$$

Voltage is limited by a **circular** limit, $\sqrt{v_d^2+v_q^2}\le V_{bus}/\sqrt3$ (the linear SVPWM region). $v_d$ gets priority so that flux control is preserved.
