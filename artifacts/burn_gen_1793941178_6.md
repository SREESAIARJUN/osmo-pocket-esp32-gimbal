# FOC Motor Control and Dual-IMU Sensor Fusion for a 3-Axis Gimbal

## Design Assumptions

I don't have access to the Job #40 specification sheet, so this design uses typical brushless gimbal hardware. Before tuning, replace the values marked **[PARAM]** with your measured values.

| Item | Assumed value |
|---|---|
| Motor | 12N14P gimbal BLDC (7 pole pairs). Typical values: R ≈ 5–15 Ω, L ≈ 1–4 mH |
| Rotor encoder | 14-bit absolute magnetic encoder (AS5048A or MT6701), one per axis |
| Current sensing | Inline or low-side shunts on 2 phases. Voltage-mode fallback is provided. |
| IMUs | 2 × ICM-42688-P on the camera plate, mounted roughly symmetric about the payload center of gravity |
| MCU | Cortex-M4F/M7 (STM32G4 or H7) with single-precision FPU |

## 1. Control Architecture

```
 θ_ref ──►[Angle P(I)+FF]──ω_ref──►[Rate PI + FF]──iq_ref──►[Current PI dq + decoupling]──►SVPWM──►Motor
              ▲                          ▲   ▲ +iq_cog(θm) +iq_fric          ▲
              │                          │   └───── Anti-cogging (LMS) ◄──────┤ θm (encoder)
        θ̂ (AHRS) ◄── ω̂ (dual-IMU, notched) ─┘                                │
                                                                     Encoder ─┘ (commutation only)
```

The rate and angle loops close on **inertial** feedback from the gyros, not on the encoder. This is what makes the gimbal reject base motion. The encoder is used only for commutation, for indexing the anti-cogging table, and for joint-limit protection.

## 2. FOC Current Loop

### 2.1 Transforms (amplitude-invariant)

Clarke transform, assuming balanced phases (i_a + i_b + i_c = 0):

$$i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}(i_a + 2 i_b)$$

Park transform, with electrical angle θ_e = p·θ_m − θ_off:

$$\begin{bmatrix} i_d\\ i_q\end{bmatrix}=\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix} i_\alpha\\ i_\beta\end{bmatrix}$$

The inverse Park transform uses the transpose of this matrix.
