# FOC Control and Dual-IMU Sensor Fusion for a 3-Axis Gimbal

I don't have the original specification for Job #37, so the parameter values below are stated assumptions. Each one is collected in a single `Params` struct so you can replace it with measured data. The math does not depend on these values. Only the gains do.

## 0. Assumptions and System Architecture

| Item | Assumed value | Symbol |
|---|---|---|
| Motor | 12N14P gimbal BLDC (2804-class), 7 pole pairs | p = 7 |
| Phase resistance / inductance | 5.6 Ω / 1.6 mH (line-to-neutral) | R, L |
| Torque constant | 0.045 N·m/A | Kₜ |
| Axis inertia (motor + payload, about the joint) | 2.5e-4 kg·m² | J |
| Encoder | 14-bit absolute magnetic (MT6701 / AS5048A) | θₘ |
| IMUs | 2× ICM-42688-P, SPI at 24 MHz, ODR = 8 kHz, ±2000 dps, ±16 g | |
| Bus voltage | 12 V | V_dc |
| MCU | Cortex-M7 / M4F with single-precision FPU | |

### Loop scheduling (per axis)

```
 PWM ISR @ 20 kHz  : ADC sample → Clarke/Park → current PI → SVPWM   (bandwidth ω_c ≈ 2π·1.5 kHz)
 IMU DRDY @ 8 kHz  : read 2× IMU → per-IMU notch/LPF → fuse → velocity PI → i_q*  (ω_v ≈ 2π·120 Hz)
 Task @ 1 kHz      : attitude estimator → angle P(+I) loop → ω*                  (ω_p ≈ 2π·20 Hz)
```

Bandwidth separation between adjacent loops is at least 6×. Any loop more than one decade below its inner loop sees the inner loop as unity gain.

### Feedback sources

- **Commutation and anti-cogging** use the encoder's mechanical angle θₘ.
- **The velocity loop** uses the inertial rate, meaning the fused gyro measurement projected onto the joint axis. This is what stabilizes the camera against base motion.
- **The angle loop** uses the camera attitude from the attitude estimator.
